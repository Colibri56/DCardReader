# אונבורדינג - פעם אחת, ואז הסקיל זוכר

המנוע כבר בנוי. בפעם הראשונה שמבקשים נוהל, נכוון אותו פעם אחת לעסק - ואז כל נוהל
עתידי כבר יוצא לפי ההעדפות שלך בלי לשאול שוב. זה שיחה קצרה: **4 שאלות חמות, אחת
בכל פעם**. בסוף נכתב `config.json`, וזהו.

> מתי לדלג: אם `config.json` כבר קיים ומאוכלס (יש בו `output.primary`), **אל
> תריץ/י אונבורדינג** - עבור/עברי ישר לבנייה. מריצים מחדש רק אם בעל/ת העסק מבקש/ת
> "לשנות הגדרות".

---

## לפני השאלה הראשונה - לקרוא, לא לשאול

קרא/י בשקט (בלי להציג לבעל/ת העסק) שני דברים, כדי **לא לשאול מה שכבר ידוע**:

1. `context/` ו-`purpose.md` בשורש ה-workspace - מי בעל/ת העסק, התחום, שמות-צוות,
   ז'רגון. זה מאפשר לנסח את ההצעות בשפה שלהם/ן (מתווך/ת = "סבב-נכס"; יועץ/ת =
   "onboarding-לקוחה"; לוגיסטיקה = "שרשור-משלוח").
2. הרץ/י `python scripts/detect_connectors.py` - מחזיר אילו מחברים נראים פעילים
   (Gmail / WhatsApp / Drive / Notion / Docs / Monday / Telegram ...). זה ה-pre-fill
   לשאלות 2 ו-3, כדי שלא נבקש מבעל/ת העסק לדקלם את מערך-הכלים.

ואז שואלים. **שאלה אחת בכל פעם**, ואחרי כל תשובה - שקף/י בחזרה במשפט אחד ("הבנתי -
את/ה...") לפני השאלה הבאה. פשוט, חם, אנושי.

---

## השאלות (4)

### שאלה 1 - מה התחום, ומי יקרא את הנהלים?
> "ספר/י לי בשורה - באיזה תחום העסק, ולמי הנהלים מיועדים בעיקר? (עובד/ת חדש/ה?
> מחליף/ה? פרילנסר/ית?)"

**למה:** קובע את הטון של הנוהל ואת רמת-הפירוט. נוהל לעובד/ת חדש/ה מפרט יותר מנוהל
לאיש/ת-צוות ותיק/ה. אם כבר עולה מ-`purpose.md` - אשר/י במקום לשאול: "ראיתי
ש... - נכון?"

### שאלה 2 - מאיפה נסיק תהליכים? (מקור)
> "כשנבנה נוהל, מאיפה הכי נוח לך שאקרא תהליך שכבר קרה - שרשור-מייל ב-Gmail?
> צ'אט-וואטסאפ? תמלול-פגישה? או שתעדיף/י פשוט להפיל קובץ בתיקייה כשצריך?"

**למה:** זה לב ה-AUTO-PULL. הצג/י קודם את מה ש-`detect_connectors.py` מצא כפעיל
("ראיתי ש-Gmail מחובר אצלך"). אם אין שום מקור דיגיטלי - זה לגמרי בסדר, נופלים
לראיון קצר או לקובץ מקומי. שום מחבר אינו חובה.

### שאלה 3 - לאן הנוהל המוגמר נשמר? (יעד)
> "ואיפה תרצה/י שהנהלים המוכנים יחיו - תיקייה במחשב? Google Docs? Notion? או
> שאשלח אותם במייל / בטלגרם?"

**למה:** קובע את `output.primary`. ברירת המחדל הבטוחה היא **קובץ מקומי** (תמיד
עובד). אם בחרו Notion/Docs ו-`detect_connectors.py` הראה שהם פעילים - מצוין; אם
לא פעילים - הסבר/י בעדינות שננפול לקובץ או ל-Sheets עד שיחברו, והנוהל עדיין מוכן.

### שאלה 4 - להפוך נהלים למשימות-onboarding? (אופציונלי)
> "שאלה אחרונה - כשעובד/ת חדש/ה מצטרף/ת, תרצה/י שאהפוך את הצ'קליסט של הנוהל
> אוטומטית למשימות בלוח (Monday / Trello / Asana / ClickUp)? או שמספיק שהצ'קליסט
> יישב בתוך הנוהל עצמו?"

**למה:** זה מה שמחבר את הנוהל לפעולה במקום מסמך-מדף. אם אין לוח חיצוני - הצ'קליסט
נשאר בתוך הנוהל (וזה לגמרי מספיק). אל תלחץ/י על מחבר; זו תוספת, לא דרישה.

## אחרי השאלות - לכתוב את config.json

מלא/י את `config.json` (במבנה של `config.example.json`) עם מה שנאסף. שדות שלא נענו
- השאר/י את ברירת המחדל (קובץ מקומי). דוגמה למה שנכתב:

```json
{
  "owner": { "domain": "תיווך נדל\"ן", "audience": "עובד/ת חדש/ה" },
  "output": { "primary": "google_docs", "local_dir": "outputs/procedures" },
  "source": { "preferred": ["gmail"], "fallback": "interview" },
  "tasks": { "board": "monday", "enabled": true },
  "scan": { "source_dir": "", "min_count": 3 },
  "language": "he-dual-gender",
  "tz_offset_hours": 3
}
```

שמור/י עם `scripts/common.py:save_config` (או פשוט כתוב/כתבי את הקובץ). סכם/י
לבעל/ת העסק במשפט אחד מה נשמר ("מעכשיו: אקרא תהליכים מ-Gmail, אשמור נהלים
ל-Google Docs, ואפתח משימות-onboarding ב-Monday - אפשר לשנות בכל רגע"). **לא
שואלים את ארבע השאלות שוב בפעמים הבאות.**
