# SOP Builder - מתעד התהליכים

הופך תהליך חוזר שחי בראש של בעל/ת העסק - לנוהל נקי, ממוספר ומוכן להעברה.
המנוע: לא לראיין מאפס, אלא להסיק את השלבים מתוך עבודה שכבר קרתה, ולתפוס לבד
תהליכים שחוזרים. בן-אדם תמיד מאשר לפני שמשהו נשמר או נשלח (human-in-the-loop).

הקובץ הזה הוא ה-orchestrator הרזה. הפירוט חי ב-`references/` - קרא/י אותם לפי הצורך,
לא הכל בכל פעם.

---

## העיקרון: החשיבה היא שלך, הרינדור הוא של הסקריפטים

ה"צעד החכם" - לקרוא שרשור-מייל או תמלול אמיתי ולהבין מה היו השלבים - מתבצע
**בסשן Claude Code של בעל/ת העסק עצמו/ה**. אין מפתח API, אין קריאת-מודל בסקריפטים,
אין תהליך-בן (subprocess) של מודל. ה-assistant הרץ בסשן הוא זה שעושה את ההסקה, ואז
מעביר ל-`scripts/build_sop.py` נוהל מוגמר כ-JSON, והוא מרנדר אותו למסמך נקי.
ככה זה חינמי, דטרמיניסטי וזהה ב-Mac וב-Windows.

---

## ה-3 מצבי-הפעלה

### 1. לפי דרישה - "תכין נוהל מהתהליך הזה"
זה ברירת המחדל. ראה/י `references/playbook.md`. בקצרה:
1. **בפעם הראשונה בלבד** - הרץ/י את האונבורדינג ב-`references/onboarding.md`
   (4 שאלות חמות, אחת בכל פעם), שכותב `config.json`. אם `config.json` כבר קיים
   ומאוכלס - דלג/י ובנה/י.
2. **הצבע/י על מקור** שבו התהליך כבר רץ - שרשור-מייל, צ'אט, תמלול, או קובץ
   מקומי שהופל בתיקייה. אם אין מקור דיגיטלי - ראיון קצר במקום (ראה/י playbook).
3. **הסק/י את השלבים מהמציאות**, מלא/י חורים הגיוניים, וסמן/י `[?]` רק על מה
   שבאמת חסר - כך הראיון מתכווץ מ-6-8 שאלות ל-2.
4. הצג/י טיוטה, קבל/י תשובה ל-2 שאלות-ההשלמה, **המתן/י לאישור** (שער-אישור).
5. הרץ/י `python scripts/build_sop.py --in sop.json` -> נוהל מעוצב נשמר ליעד
   שנבחר באונבורדינג, עם הפלייסבק לרביעייה אם המחבר חסר.
6. אופציונלי: הזרם/י את הצ'קליסט-הסופי כמשימות-onboarding (`references/connectors.md`).

### 2. פרואקטיבי - "תפוס לי תהליכים לתעד" (היצע, לא ביקוש)
המנוע האמיתי. הרץ/י `python scripts/scan_repeats.py` על תיקיית-תקשורת מקומית
(או על שרשורים ש-Claude משך מ-Gmail/WhatsApp). הוא מקבץ שרשורים דומים ומחזיר
מועמדים שחזרו 3 פעמים+. לכל מועמד שלח/י שער-אישור בטלגרם
(`python scripts/notify.py --text "..." --approve`). באישור - חזור/חזרי למצב 1
על ה-members של אותו אשכול.

### 3. תחזוקה - "התהליך הזה השתנה?"
אחת לרבעון, השווה/י נוהל קיים לאיך שהתהליך רץ בפועל (לפי שרשורים חדשים), והצע/י
עדכון **לאישור** לפני ששומרים גרסה חדשה. אותו זרימה כמו מצב 1, רק שמתחילים מנוהל
קיים.

> הערה: הסקיל הזה הוא on-demand, אבל המנוע-הפרואקטיבי (מצב 2) הופך ללופ-אוטומטי
> שבועי/חודשי בשתי שורות - ב-Mac/Linux דרך `cron` וב-Windows דרך Task Scheduler.
> הפקודות המדויקות לכל מערכת-הפעלה נמצאות ב-`references/playbook.md` (מסלול ג').
> זה לא חובה - הערך מלא גם בהרצה ידנית - אבל ככה ההיצע באמת רץ בלי שצריך לזכור.

## הרביעייה האוניברסלית - הליבה לעולם לא נשברת

הסקיל עובד **באפס אינטגרציות** על: קובץ מקומי -> Google Sheets -> Gmail -> Telegram.
בעל/ת העסק בוחר/ת את היעד באונבורדינג; הליבה אף פעם לא תלויה במחבר חיצוני.

- **קובץ מקומי** - תמיד זמין. `build_sop.py` כותב Markdown לתיקיית 'נהלים'.
- **Google Sheets / Gmail / Telegram** - היעדים האחרים של הרביעייה.
- **מחברים אופציונליים** (Notion / Docs / Drive כמאגר; Monday / Trello / Asana /
  ClickUp למשימות) הם **בחר-פנימה, לא חובה**. אם יש Notion - מציעים אותו; אם אין -
  נופלים לקובץ או ל-Sheets. ההחלפה תמיד מפורשת. הפירוט ב-`references/connectors.md`.

## התאמה לבעל/ת העסק

לפני בנייה, קרא/י את `context/` ו-`purpose.md` של בעל/ת העסק (אם קיימים) כדי
להתאים את ההסקה, את זיהוי-החוזר ואת השאלות לתחום: מתווך/ת = סבב-נכס; יועץ/ת =
onboarding-לקוחה; מנהל/ת-לוגיסטיקה = שרשור-משלוח. השתמש/י בז'רגון נכון ובשמות-צוות
אמיתיים. `python scripts/detect_connectors.py` מזהה אילו מחברים פעילים כדי להציע
מאגר-נהלים ולוח-משימות מתאימים.

## כלל הכתיבה

- כל טקסט שפונה לבעל/ת העסק ולכל עובד/ת = **עברית דו-מגדרית** (לא רק "אתה").
- פיסוק: מקף רגיל ( - ) בלבד. לעולם לא en-dash או em-dash, בשום שפה.
- שום מידע לא נשמר ולא נשלח בלי אישור אנושי מפורש.

## קבצים בערכה

| קובץ | מה הוא |
|---|---|
| `references/onboarding.md` | זרימת האונבורדינג (פעם ראשונה) - 4 שאלות, כותב config.json |
| `references/playbook.md` | מנוע ה-multi-step המלא (הסקה, ראיון, טיוטה, שער-אישור) |

| `scripts/build_sop.py` | מרנדר נוהל מ-JSON למסמך Markdown נקי + צ'קליסט |
| `scripts/scan_repeats.py` | המנוע הפרואקטיבי - מקבץ שרשורים, מזהה תהליך-חוזר |
| `scripts/detect_connectors.py` | סורק אילו מחברים זמינים (read-only, לא מאמת) |
| `scripts/notify.py` | שער-אישור / התראה דרך Telegram (עם פלייסבק להדפסה) |
| `scripts/common.py` | עזרי-בסיס: שורש-workspace, config, יעד-פלט, זמן |
| `config.example.json` | מבנה ה-config שהאונבורדינג כותב |
