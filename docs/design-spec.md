# הקורא בקלפים · מסמך הנחיות עיצוב ל־Claude Code

> **למי המסמך:** ל־Claude Code שמיישם את העיצוב החדש בתוסף הוורדפרס "הקורא בקלפים".
> **מקור:** הדמיית העיצוב שאושרה (לשונית "כיוון בהיר"). צילומי מסך מההדמיה יצורפו לכל שלב.
> **היקף השלב הזה:** עיצוב בלבד. לא משנים את הלוגיקה של ה-AI, לא נוגעים בתשלומים, ולא מוסיפים אזור אישי.

---

## 0. כללי עבודה (חובה לקרוא לפני כל שלב)

1. **עובדים בשלבים** (סעיף 9). בכל שלב: קודם מציגים תוכנית קצרה ומחכים לאישור, אחר כך משנים קוד, ובסוף עושים commit עם הודעה ברורה.
2. **לא משנים התנהגות קיימת** מעבר למה שכתוב כאן: חיבור ל-AI, התאמת לשון זכר/נקבה, שליחת מייל (בצד השרת), מגבלת 3 קלפים, הקלטה קולית ומשוב אגודל.
3. **RTL מלא:** `dir="rtl"` ו־`lang="he"`. משתמשים ב־logical properties (`margin-inline-start` וכו') ולא ב־left/right, חוץ מבאנימציות.
4. **לשון פנייה:** כל טקסט שמופיע כאן בשתי גרסאות (נ׳ / ז׳) נבחר לפי מה שהמשתמש סימן בחלון "נעים להכיר". לפני שהמשתמש בחר, משתמשים בלשון רבים.
5. **רספונסיביות:** נקודת שבירה אחת עיקרית, `768px`. מתחתיה פריסת טלפון, ומעליה פריסת מחשב. אין גלילה אופקית בעמוד, חוץ משורת הקלפים בטלפון.
6. **נגישות:**
   - כפתורים אמיתיים (`<button>`) וקישורים אמיתיים (`<a href>`).
   - לכל כפתור שיש בו רק אייקון יש `aria-label`.
   - פוקוס מקלדת גלוי (`outline: 3px solid var(--bordeaux); outline-offset: 3px`).
   - יעד לחיצה של 44×44px לפחות.
   - כבוד ל־`prefers-reduced-motion` (סעיף 7.8).
   - התוסף הקיים לנגישות נשאר.
7. **בלי ספריות חדשות** לאנימציה. CSS transitions ו־JavaScript רגיל מספיקים.
8. **מזהים ייחודיים:** כל ה-CSS של העיצוב החדש נכתב תחת קידומת אחת, `.kb-` (קיצור של "הקורא בקלפים"), כדי לא להתנגש בתבנית הוורדפרס.

## 1. צבעים (CSS variables)

```css
.kb-app {
  --paper:        #FBF8F6; /* רקע כללי */
  --surface:      #FFFFFF; /* תיבות, כרטיסים, מסגרת קלף */
  --ink:          #2A2326; /* טקסט ראשי */
  --ink-soft:     #4A3F43; /* טקסט גוף משני */
  --muted:        #6E6266; /* טקסט עזר, תוויות קטנות */
  --line:         #E6DCDE; /* קווי הפרדה, מסגרות עדינות */
  --line-strong:  #D9C9CD; /* מסגרת שדות קלט וכפתור משני */
  --bordeaux:     #7D2E46; /* צבע מוביל: כפתור ראשי, לוגו, הדגשות */
  --bordeaux-hover:#692539;
  --blush:        #F3E7EA; /* רקע עדין: בועת משתמש, כפתור מיקרופון, אזור "רוצה להעמיק?" */
  --dashed:       #C9AEB6; /* מסגרת מקווקוות של "קלף נוסף" */
  --scrim:        rgba(42,35,38,0.45); /* רקע כהה מאחורי חלונות */
  --shadow-card:  0 18px 40px rgba(42,35,38,0.16);
  --shadow-small: 0 4px 10px rgba(42,35,38,0.16);
}
```

**כללים:**
- **צבע מוביל אחד, בורדו.** אין אדום בוהק, אין שחור ואין אפור כהה בכפתורים.
- **טקסט לבן מופיע רק על בורדו.**
- **בלי גרדיאנטים בכלל**, והרקע אחיד בצבע `--paper`.
- **כפתור הנגישות של התוסף החיצוני:** לשנות את צבעו ל־`#7D2E46` בהגדרות התוסף. זה לא בקוד שלנו.

## 3. רכיבים

### 3.1 כפתורים (ארבעה סוגים בלבד)

```css
.kb-btn { font-family: 'Rubik', sans-serif; font-weight: 500; border-radius: 999px; min-height: 44px; padding: 0 22px; cursor: pointer; }
.kb-btn--primary   { background: var(--bordeaux); color: #fff; border: none; }            /* פעולה ראשית אחת במסך */
.kb-btn--primary:hover { background: var(--bordeaux-hover); }
.kb-btn--secondary { background: var(--surface); color: var(--ink); border: 1.5px solid var(--line-strong); }
.kb-btn--emphasis  { background: var(--surface); color: var(--bordeaux); border: 2px solid var(--bordeaux); } /* "שאלה חדשה" */
.kb-btn--link      { background: none; border: none; color: var(--bordeaux); font-weight: 400; text-decoration: underline; text-underline-offset: 4px; padding: 0 6px; } /* "לתת משוב": משקל רגיל, אייקון בקו בלבד */
.kb-btn:disabled   { background: var(--line); color: var(--muted); border: none; cursor: default; }
/* מצבי ריחוף ולחיצה: עדינים בלבד. אף כפתור לא נצבע בוורוד או באדום, בשום מצב */
.kb-btn--secondary:hover, .kb-btn--emphasis:hover { background: var(--blush); }
.kb-btn--link:hover { color: var(--bordeaux-hover); }
.kb-btn:active { transform: translateY(1px); }
```
- כפתור ראשי גדול: גובה 56px וגודל טקסט 18px.
- **"ביטול" בחלונות הוא תמיד כפתור שקט:** טקסט בצבע `--muted`, בלי רקע ובלי מסגרת. **אסור** שיהיה מלא או צבעוני.
- **לנטרל את עיצוב הכפתורים של התבנית:** כל כפתור של האפליקציה מקבל את המחלקה `.kb-btn`, וב-CSS שלנו מאפסים לפניה את ה־`background`, ה־`color` וה־`border` שמגיעים מהתבנית, כולל מצבי `:hover`, `:focus` ו־`:active`.
- **לכל כפתור יש מסגרת**, חוץ מהכפתור הראשי (מלא) והקישור "לתת משוב". "שליחת השיחה במייל" ו"סיום השיחה" הם `--secondary`: מסגרת דקה `1.5px solid var(--line-strong)`, רקע לבן וטקסט כהה (`--ink`), **לא** בורדו ולא טקסט בלי מסגרת.
- כל האייקונים בממשק הם קו בלבד (stroke) ברוחב 1.7–1.8, בלי מילוי ובלי אימוג'י.
- **כפתורי בחירת המסלול במסך הבית** הם כפתורים מלבניים עם פינות 18px, ובהם שתי שורות (שם ותיאור). ראו סעיף 6.3.

### 3.2 שדות קלט ותיבת טקסט עם מיקרופון
- רקע לבן, מסגרת `1.5px solid var(--line-strong)`, פינות 14–20px וטקסט 17–18px.
- **אין ידית לשינוי גודל:** `resize: none`.
- כפתור המיקרופון: עיגול 44px, רקע `--blush` ואייקון בבורדו. הוא יושב בתוך התיבה, בפינה התחתונה בצד שמאל.
- **כפתור שליחה** (במסך השיחה): עיגול 44px, רקע בורדו וחץ לבן שמצביע שמאלה, 20px (סעיף 3.2א).
- לכל שדה יש `<label>` גלוי מעליו, למשל "השאלה שלך" או "התשובה שלך".
- **פוקוס בשדות טקסט:** מסגרת אחת בלבד. במצב פוקוס המסגרת עצמה משתנה ל־`2px solid var(--bordeaux)`, עם הילה רכה `box-shadow: 0 0 0 3px rgba(125,46,70,.12)`, **בלי `outline` נוסף**, כדי שלא תיווצר מסגרת כפולה. אותו מראה בדיוק בכל השדות ובכל המצבים (מסר ודיאלוג).

### 3.2א אייקונים: גודל קבוע ותמיד SVG
- **כל אייקון הוא `<svg>` שמוטמע ישירות ב-HTML**, עם `width` ו־`height` **גם כמאפיינים וגם ב־CSS**. לא פונט אייקונים, לא תמונה ולא אימוג'י.
- **תבניות וורדפרס נוטות להקטין או למתוח SVG** (כללים כמו `svg { max-width: 100% }` או `button svg { width: 1em }`). לכן מגדירים מחלקה ייעודית עם עדיפות גבוהה:
```css
.kb-app .kb-icon { width: 20px !important; height: 20px !important; min-width: 20px; flex: none; display: block; }
.kb-app .kb-icon--sm { width: 18px !important; height: 18px !important; min-width: 18px; }
.kb-app .kb-icon-btn { width: 44px; height: 44px; min-width: 44px; padding: 0; display: inline-flex; align-items: center; justify-content: center; font-size: 0; line-height: 0; }
```
- **גדלים:** בכפתורים העגולים (שליחה, מיקרופון, ☰) האייקון 20px בתוך עיגול של 44px. אגודלים: 18px בתוך אזור לחיצה של 38–40px.
- **כפתור השליחה כשהתיבה ריקה:** מושבת, רקע `--line` וחץ בצבע `--muted`, **באותו גודל** כמו במצב הפעיל.

### 3.3 קלף
| מצב | צורה | פרטים |
|---|---|---|
| **גב קלף** (בחפיסה) | **עומד** (יחס 2:3) | רקע בורדו, מסגרת לבנה 3px, פינות 12–14px, קו פנימי דק `rgba(243,231,234,.5)` במרחק 6–8px מהקצה, וסמל הלוגו (סעיף 4) במרכז בצבע `#F3E7EA` |
| **קלף שנשלף** (מסך הקריאה ומסך המסר) | **לרוחב** (יחס 4:3) | מסגרת לבנה 8–12px, פינות 14–16px, `box-shadow: var(--shadow-card)`, והתמונה **ממלאת את כל הקלף** (`object-fit: cover`) עם פינות 7–8px. הטיה קלה של ‎-1.5° עד ‎+1.5°, שונה לכל קלף |

**חשוב:** תמונות מהחפיסה לא מופיעות בשום מקום אחר באפליקציה, כולל מסך הבית ודף הכניסה. שם משתמשים רק בגבי קלפים, **ותמיד עומדים** (2:3), לעולם לא לרוחב. רק קלף שנשלף ונחשף מוצג לרוחב.

### 3.4 חלונות קופצים (bottom sheet בטלפון, modal במחשב)
- **רקע:** `--scrim`.
- **בטלפון:** גיליון שעולה מלמטה, ברוחב מלא, עם פינות עליונות של 28px, רקע `--paper`, ידית קטנה למעלה (44×5px, `--line`) וריווח פנימי `14px 24px 34px`.
- **במחשב:** חלון במרכז המסך ברוחב מקסימלי 520px, עם פינות 24px.
- **מבנה קבוע:** כותרת, משפט הסבר קצר, שדות, כפתור ראשי אחד, ומתחתיו כפתור משני שקט ("ביטול").
- **סגירה:** ב־Esc, בלחיצה על הרקע ובכפתור "ביטול". הפוקוס נשאר כלוא בתוך החלון ונעבר לשדה הראשון כשהחלון נפתח.
- **אסור** להשתמש ב־`window.prompt` או ב־`window.alert`. החלון האפור של הדפדפן, "staging... says", יוצא לגמרי.

### 3.5 הודעות בשיחה
- **הודעת AI:** **בלי בועה.** מעל הטקסט מופיעה שורה קטנה: עיגול 34px ברקע `--blush` עם סמל הלוגו, והמילה "הקורא" בגודל 15px בצבע `--muted`. מתחתיה הטקסט ב־19px עם גובה שורה 1.8, ופסקאות נפרדות.
- **אגודל למעלה ולמטה:** **אותו SVG בדיוק בשניהם.** באגודל למטה מסובבים את כל ה-SVG (`transform: rotate(180deg)`). לא משתמשים בצורה אחרת ולא בהיפוך מראה. סדר: אגודל למעלה מימין, אגודל למטה משמאל. שני כפתורי אייקון שקטים מתחת להודעת ה-AI. גודל 36–40px, קו דק בצבע `--muted`, בלי רקע ובלי אימוג'י. כשלוחצים, האייקון נצבע בבורדו.
- **הודעת משתמש:** בועה בצבע `--blush` עם טקסט כהה, פינות `20px 20px 20px 6px`, מיושרת לצד שמאל (סוף השורה ב־RTL) וברוחב מקסימלי של 75%.
- **הודעת שגיאה:** **לא** מופיעה כבועה. היא מוצגת כשורת התראה מתחת לשיחה, עם רקע `--blush`, פינות 14px, ריווח `12px 16px` וטקסט 15px:
  > החיבור נקטע לרגע. ההודעה שלך לא אבדה.  **[ניסיון חוזר]**

  "ניסיון חוזר" שולח שוב את ההודעה האחרונה. אם גם הניסיון השני נכשל, מוסיפים את הכפתור "שאלה חדשה". על הודעת שגיאה אין אגודלים.

### 3.5א שגיאות ואימות שדות (כלל: אין חלונות של הדפדפן)

**אסור בשום מקום באפליקציה:** `alert()`, `confirm()` ו־`prompt()`. כל הודעה מופיעה בתוך הממשק, ליד המקום שבו היא רלוונטית.

**שלושה סוגי הודעות, ולא יותר:**

| סוג | מתי | איך נראה |
|---|---|---|
| **שגיאת שדה** | שדה ריק או לא תקין | מסגרת השדה הופכת ל־`2px solid var(--error)`. מתחת לשדה מופיעה שורה של 14px בצבע `--error`, עם אייקון עיגול-סימן-קריאה קטן (16px). השדה מקבל `aria-invalid="true"` ו־`aria-describedby` שמצביע על ההודעה, והפוקוס עובר אליו. ההודעה **נעלמת ברגע שמתחילים להקליד** |
| **שורת התראה** | תקלה בתקשורת עם השרת | לפי סעיף 3.5: רקע `--blush`, טקסט כהה וכפתור פעולה ("ניסיון חוזר") |
| **כפתור מושבת** | פעולה שעוד לא אפשרית | הכפתור מושבת (`disabled`) ואין הודעה. למשל: כפתור השליחה בשיחה מושבת כל עוד התיבה ריקה |

```css
.kb-app { --error: #A3262A; } /* אדום-חום כהה. ניגודיות טובה על --paper, ושונה מהבורדו של המותג */
.kb-field-error { display: flex; align-items: center; gap: 6px; margin-top: 6px; font-size: 14px; color: var(--error); }
.kb-input[aria-invalid="true"] { border: 2px solid var(--error); }
```
- מבדילים בין שגיאה לרגיל **גם באייקון ובטקסט**, ולא רק בצבע.
- הטקסטים לא מתנצלים ("סליחה", "אופס"), ותמיד אומרים מה לעשות.
- כל ההודעות בלשון הפנייה הנכונה. לפני שהמשתמש בחר לשון, משתמשים ברבים.

**כל ההודעות:**

| מצב | סוג | טקסט |
|---|---|---|
| ניסיון להתחיל בלי שאלה (מסך הבית) | שגיאת שדה | נ׳: כתבי את השאלה שלך, ואז נתחיל. / ז׳: כתוב את השאלה שלך, ואז נתחיל. |
| "נעים להכיר": בלי שם | שגיאת שדה | רשמו את השם, כדי שנוכל לפנות אליכם. |
| "נעים להכיר": בלי לשון פנייה | שגיאת שדה (מתחת לשתי האפשרויות) | סמנו איך לפנות אליכם. |
| מייל לא תקין | שגיאת שדה | הכתובת לא נראית תקינה. כדאי לבדוק שאין רווחים ושיש @ |
| תשובה ריקה בשיחה | כפתור מושבת | (אין הודעה) |

### 6.5 מסך דיאלוג מכוון
- **זה מסך נפרד, לא המשך של מסך הבית.** ברגע שהשאלה נשלחה, **כל חלק מסך הבית נעלם**: הברכה, הכותרת "מה מעסיק אותך היום?", הפסקה, תיבת השאלה, כפתורי המסלול וגבי הקלפים הדקורטיביים. **אין** תווית "זה הקלף שנבחר", **ואין** בועה "שאלת: …", כי השאלה כבר מוצגת.
- **מבנה של אפליקציית צ'אט:** המסך תופס בדיוק את גובה החלון (`height: 100dvh`). **השאלה והקלפים קבועים** ולא נגללים, **רק השיחה נגללת**, ו**תיבת התשובה קבועה בתחתית**. המשתמש אף פעם לא צריך לגלול הלוך וחזור כדי לראות את התמונה או להגיע לתיבה.

**במחשב (מעל 1024px): שתי עמודות**
```
┌──────────────────────────────── header ────────────────────────────────┐
│ ┌──── עמודת צד (380px, ימין) ────┐ ┌──────── עמודה רחבה ─────────────┐ │
│ │ הקלפים שלך                     │ │ השאלה שלך (קבועה, מלאה, 24px)    │ │
│ │ [קלף 1, לרוחב]                 │ ├──────────────────────────────────┤ │
│ │ [קלף 2]                        │ │  ↕ ההודעות נגללות (עד 680px)     │ │
│ │ צריך עוד קלף?                  │ │                                  │ │
│ │ ───────────                    │ ├──────────────────────────────────┤ │
│ │ [שאלה חדשה]                    │ │  תיבת התשובה                     │ │
│ │ [שליחת השיחה במייל]            │ └──────────────────────────────────┘ │
│ │ [סיום השיחה]   לתת משוב         │                                      │
│ └────────────────────────────────┘                                      │
└─────────────────────────────────────────────────────────────────────────┘
```
- **השאלה נמצאת בראש העמודה הרחבה, לא בעמודת הצד.** היא מוצגת **במלואה**: בלי חיתוך, בלי גלילה פנימית ובלי `line-clamp`, גם כשהיא ארוכה. 24px, משקל 500, צבע `--ink`, ומעליה "השאלה שלך" (14px, `--muted`). היא **קבועה** בראש העמודה, ההודעות נגללות מתחתיה, ומתחתיה קו `--line`.
- **עמודת הצד** (380px, מימין, עם קו הפרדה `--line`): "הקלפים שלך" (14px, `--muted`), הקלפים זה מתחת לזה (לרוחב, באותו גודל) והקישור "צריך עוד קלף?". **מיד אחרי הקלפים**, עם רווח של 24px, באים כפתורי הפעולות. הכפתורים **לא** מוצמדים לתחתית העמודה, ולכן אין חלל ריק לפניהם. הם מסודרים **אחד מתחת לשני, כל אחד ברוחב מלא של העמודה** (`width: 100%`), ו"לתת משוב" ממורכז מתחתיהם. אם התוכן גבוה מהחלון, **העמודה נגללת**, ושום כפתור לא נחתך.
- **העמודה הרחבה:** בראשה השאלה, מתחתיה ההודעות ברוחב קריאה של עד 680px, ובסוף תיבת התשובה. **תיבת התשובה צמודה להודעה האחרונה** כל עוד השיחה קצרה, ולא נזרקת לתחתית המסך. רק כשהשיחה ממלאת את הגובה, ההודעות נגללות והתיבה נשארת קבועה בתחתית. מבחינה טכנית: העמודה היא `display:flex; flex-direction:column`, השאלה `flex: none`, אזור ההודעות `flex: 0 1 auto; min-height: 0; overflow-y: auto`, והתיבה `flex: none`.
- **גובה המסך, כדי שהתיבה לעולם לא תיחתך:** התבנית מוסיפה מעל האפליקציה מרווחים, ולפעמים גם סרגל ניהול, ולכן אי אפשר לנחש את הגובה ב-CSS בלבד. מחשבים אותו ב-JS: `container.style.height = (window.visualViewport?.height ?? innerHeight) - container.getBoundingClientRect().top + 'px'`, ומעדכנים ב־`resize` וב־`visualViewport.resize`. **לבדוק ב־1366×768, ב־1920×1080 ובזום דפדפן של 125%.** בכל המצבים התיבה וכפתוריה גלויים במלואם בלי לגלול את העמוד.

**בטלפון: רצועה קבועה למעלה ותיבה קבועה למטה**
- **רצועה קבועה מתחת לכותרת:** "השאלה שלך:" ואחריה השאלה (16px). עד 3 שורות מוצגות במלואן. אם השאלה ארוכה יותר, היא נחתכת עם … ולידה קישור קטן **"הצגת השאלה המלאה"** שפותח אותה.  ומתחתיה **תמונות ממוזערות** של הקלפים (76×57px, מסגרת לבנה 3px). **הקשה על תמונה ממוזערת פותחת את הקלף בגדול** בשכבה מעל המסך (רקע `--scrim`, הקלף ברוחב המסך, וסגירה בהקשה או ב־×). לרצועה יש קו תחתון וצל עדין.
- **אזור השיחה נגלל.** כפתורי הפעולות מופיעים **בסוף השיחה** ונגללים איתה, כדי שלא יתפסו מקום קבוע.
- **תיבת התשובה קבועה בתחתית:** 2 שורות בהתחלה, גדלה עד 6 שורות. היא צריכה להישאר מעל המקלדת כשהמקלדת פתוחה (`100dvh` ו־`visualViewport`).
- "צריך עוד קלף?" מופיע ברצועה, אחרי התמונות הממוזערות, באותו סגנון שקט.

**המתנה לתשובה מהקורא: המסך אף פעם לא ריק.**
- **מיד** כשהקלף נוחת (וגם אחרי כל הודעה של המשתמש), מופיעה בעמודה הרחבה שורת "הקורא" עם **סימן הקלדה**: שלוש נקודות של 6px בצבע `--muted`, שמהבהבות בזו אחר זו. לידן טקסט שקט (15px, `--muted`):
  - לפני התשובה הראשונה: "הקורא מתבונן בקלף ובשאלה שלך…"
  - בהמשך השיחה: "הקורא כותב…"
- כשהתשובה מגיעה, היא מחליפה את השורה הזו באותו מקום, בלי קפיצה.
- אם עוברות 20 שניות בלי תשובה, השורה מתחלפת בשורת השגיאה מסעיף 3.5, עם "ניסיון חוזר".

**התנהגות הגלילה (בשתי הגרסאות):**
- כשמגיעה הודעה חדשה, אזור השיחה גולל אליה בעדינות, **אלא אם** המשתמש גלל למעלה כדי לקרוא הודעה קודמת. במקרה כזה לא קופצים, ומציגים כפתור קטן "↓ הודעה חדשה" מעל תיבת התשובה.
- **תיבת התשובה במחשב:** 3 שורות בהתחלה, גדלה עד כ־10 שורות.

- **"צריך עוד קלף?" מוצנע בכוונה.** זו אפשרות למקרים קיצוניים, ואנחנו לא רוצים לעודד אותה:
  - **קישור טקסט קטן בלבד**, בלי מסגרת, בלי קופסה ובלי אייקון +. 14px, צבע `--muted`, קו תחתון דק.
  - **מופיע רק אחרי שהמשתמש ענה לפחות פעם אחת בשיחה.** אין מונה, ואחרי הקלף השלישי הקישור נעלם.
- **קלף נוסף משתמש באותה אנימציה של סעיף 7,** בגרסה קצרה: בלי שלב הריפל, ישר לזרימה בין הערימות.
  - היא נפתחת כ**שכבה על כל המסך**, ברקע `--paper` (לא שקוף) ועם כפתור × לסגירה. **לא בתוך העמודה הרחבה ולא מעל השיחה.** כך האנימציה לא מתנגשת בטקסט.
  - **ריווח קבוע:** בין הבמה (כולל עובי הערימות) לשורת ההנחיה יש 24px, ובין ההנחיה לכפתור 16px. ההנחיה והכפתור לעולם לא עולים על הקלפים.
  - אחרי החשיפה: "להמשך הקריאה" סוגר את השכבה. הקלף מופיע בעמודת הצד (במחשב) או ברצועת התמונות הממוזערות (בטלפון), ומיד מופיע סימן ההקלדה של הקורא.

| רכיב | טקסט |
|---|---|
| שם השולח בהודעות ה-AI | הקורא |
| תווית תיבת התשובה | התשובה שלך (מוסתרת ויזואלית, `sr-only`, כי התיבה קבועה ומובנת מעצמה. נשארת לקוראי מסך) |
| placeholder | נ׳: כתבי מה עולה בך, או שאלי שאלת המשך / ז׳: כתוב מה עולה בך, או שאל שאלת המשך |
| קישור קלף נוסף | צריך עוד קלף? |
| כפתורי פעולות | **שאלה חדשה** (`--emphasis`) · שליחת השיחה במייל (`--secondary`) · סיום השיחה (`--secondary`) · **לתת משוב** (`--link` עם אייקון בועת דיבור). מחשב: בתחתית עמודת הצד, אחד מתחת לשני. טלפון: בסוף השיחה |

- מעל כפתורי הפעולות יש קו `1px solid var(--line)`.
- **"סיום השיחה" ו"שאלה חדשה" לא פותחים את חלון המשוב.**

### 6.6 מסך קבלת מסר אישי
- בראש המסך "השאלה שלך" והשאלה, ומתחתן **קלף אחד לרוחב**.
- אחר כך הודעת ה-AI עם הכותרת **"הקורא – המסר שלך ממני"** (באותו מבנה כמו "הקורא": אוואטר קטן משמאל לטקסט), והאגודלים.
- **אזור "רוצה להעמיק?"** (במקום הכפתור האפור "להמשיך ולהעמיק בשיחה"): קופסה ברקע `--blush`, פינות 18px וריווח 20px.
  | רכיב | טקסט |
  |---|---|
  | כותרת (19px) | רוצה להעמיק? |
  | הסבר (15px) | אפשר להמשיך מכאן לדיאלוג מכוון, עם אותה שאלה ואותו קלף. הקורא ישאל אותך שאלות ויעזור לך להגיע לתשובה מדויקת יותר. |
  | כפתור ראשי | המשך לדיאלוג מכוון |
- **במצב מסר אין תיבת תשובה בכלל.**
- **לחיצה על "המשך לדיאלוג מכוון":**
  1. האזור "רוצה להעמיק?" נעלם.
  2. **הקורא כותב מיד הודעת פתיחה** לדיאלוג, ששואלת שאלה ראשונה. מבקשים אותה מה-AI (עם השאלה, הקלף והמסר שכבר ניתן), ועד שהיא מגיעה מוצג **סימן הקלדה**: שלוש נקודות קטנות בצבע `--muted` מתחת ל"הקורא". אם ה-AI לא עונה, משתמשים בטקסט קבוע: נ׳ "בואי נעמיק. מה הדבר הראשון שמשך את עינך בתמונה?" / ז׳ "בוא נעמיק. מה הדבר הראשון שמשך את עינך בתמונה?"
  3. **רק אחרי שהודעת הפתיחה מופיעה**, נפתחת תיבת התשובה. אף פעם לא מוצגת תיבה ריקה בלי שאלה מהקורא.
- ההודעה בסוף המסר שמזמינה ללחוץ על "להמשיך ולהעמיק בשיחה" **מיותרת עכשיו**. צריך להסיר אותה מהנוסח שה-AI מחזיר, או לסנן אותה בתצוגה.
- **שורת פעולות:** שאלה חדשה (`--emphasis`), שליחה במייל, סיום, ו"לתת משוב".

## 7. ערבוב ושליפה: מפרט מלא

### 7.1 העיקרון
המשתמש צריך **להרגיש שהוא בוחר**. לכן הקלפים לא נחים על השולחן. הם זורמים מערימה לערימה, והמשתמש **עוצר** את הזרימה. הקלף שבתנועה באותו רגע הוא שלו.

### 7.2 האקראיות בצד השרת (חובה)
- **האנימציה רק מציגה.** איזה קלף מבין ה־72 ייצא נקבע **בשרת**, ברגע הלחיצה, למשל בבקשת AJAX קיימת או חדשה, עם `random_int()` של PHP.
- הלקוח שולח בקשה, מקבל בחזרה `{ id, image_url, alt }`, וטוען את התמונה **מראש** (`new Image()`). ההיפוך מתחיל רק כשהתמונה נטענה **וגם** עבר זמן ההרמה המינימלי.
- **אם השרת לא עונה תוך 8 שניות, או מחזיר שגיאה:** הקלף חוזר לערימה, הזרימה ממשיכה, **וכפתור "שליפת קלף" חוזר להופיע**. במקום שורת ההנחיה מופיעה שורת השגיאה (סעיף 3.5): "הקלף לא נשלף בגלל תקלה בחיבור." עם כפתור **"ניסיון חוזר"**, שעושה בדיוק את מה שעושה "שליפת קלף". המשתמש אף פעם לא נשאר בלי דרך להמשיך.
- הקלפים בחפיסה המונפשת הם **גבי קלפים בלבד**, בלי קשר לתמונות האמיתיות.

**איזה קלף נבחר:**
- **לחיצה על "שליפת קלף":** הקלף **האחרון שזז**, כלומר זה שבתנועה או שזה עתה נחת.
- **הקשה ישירה על קלף בכל אחת מהערימות:** הקלף שהוקש. הקשה עובדת רק בשלב `flow`.
- בשני המקרים, התמונה שמתגלה היא זו **שהשרת החזיר**.

```js
  }

  function setT(id, { x=0, y=0, r=0, ry=0, s=1, dur=420, delay=0, zi }) {
    const el = cards[id];
    el.style.transition = reduce ? 'none' : `transform ${dur}ms cubic-bezier(.2,.7,.2,1) ${delay}ms`;
    el.style.transform = `translate(${x}px,${y}px) rotate(${r}deg) rotateY(${ry}deg) scale(${s})`;
    if (zi !== undefined) el.style.zIndex = zi;
  }
  function render() {
    for (let id = 0; id < P.N; id++) {
      if (id === chosen) continue;
      const p = order.indexOf(id);
      if (phase === 'stack')  setT(id, { y: -p*1.2, r: jit(id,4)*1.5, delay: p*25, zi: p });
      if (phase === 'split') { const L = p < P.N/2;
        setT(id, { x: L ? -P.PX : P.PX, y: -(L ? p : p - P.N/2)*1.5, r: L ? -6 : 6, delay: (p%4)*30, zi: p }); }
      if (phase === 'riffle') setT(id, { y: -p*1.2, r: jit(id,4)*1.5, dur: 340, delay: p*60, zi: p });
      if (phase === 'flow' || phase === 'drawn') {
        const ia = A.indexOf(id), ib = B.indexOf(id);
        const push = phase === 'drawn' ? P.PUSH : 0, dy = phase === 'drawn' ? P.PUSHY : 0;
        let x = ia >= 0 ? P.PX + push : -P.PX - push, y = -(ia >= 0 ? ia : ib) * 1.2 + dy;
        let r = jit(id,5) * 3; if (id === last && phase === 'flow') r += dir === 'AB' ? -4 : 4;
        setT(id, { x, y, r, dur: phase === 'drawn' ? 600 : 300, zi: z[id] ?? p });
      }
    }
  }
  function riffle(o) {                                                    // שזירה אקראית
    const cut = Math.floor(o.length/2) + (Math.random() < .5 ? -1 : 1);
    const a = o.slice(0, cut), b = o.slice(cut), out = [];
    while (a.length || b.length) out.push((a.length && (!b.length || Math.random() < .5)) ? a.shift() : b.shift());
    return out;
  }
  function step() {                                                       // מעבר קלף אחד
    const src = dir === 'AB' ? A : B, dst = dir === 'AB' ? B : A;
    const id = src.pop(); dst.push(id); z[id] = ++zc; last = id;
    if (!src.length) dir = dir === 'AB' ? 'BA' : 'AB';
    render();
  }
  async function pick(id) {
    if (phase !== 'flow' || chosen !== null) return;
    clearInterval(flowTimer); phase = 'drawn'; chosen = id;
    A = A.filter(x => x !== id); B = B.filter(x => x !== id);
    opts.onBusyChange(true); render();
    setT(id, { x: 0, y: P.PY, r: -1, s: P.S, dur: 750, zi: 9999 });       // lift
    const minLift = new Promise(r => setTimeout(r, 700));
    try {
      const card = await Promise.race([opts.fetchCard(), new Promise((_, rej) => setTimeout(() => rej('timeout'), 8000))]);
      const img = cards[id].querySelector('.kb-front-inner img');
      await new Promise((res, rej) => { img.onload = res; img.onerror = rej; img.src = card.image_url; img.alt = card.alt; });
      await minLift;
      setT(id, { x: 0, y: P.PY, r: -1, ry: 180, s: P.S, dur: 750, zi: 9999 });   // flip (עומד)
      later(800, () => {
        setT(id, { x: 0, y: P.PY, r: 90, ry: 180, s: P.SL, dur: 750, zi: 9999 }); // land (לרוחב)
        later(800, () => { opts.onHint('revealed'); opts.onReveal(card); });
      });
    } catch (e) {                                                          // החזרה לזרימה ושגיאה
      chosen = null; phase = 'flow'; A.push(id); render(); opts.onHint('error'); opts.onBusyChange(false);
      flowTimer = setInterval(step, P.FLOW);
    }
  }
  function start({ skipRiffle = false } = {}) {                          // skipRiffle: ל"קלף נוסף"
    opts.onBusyChange(true); opts.onHint('shuffling'); render();
    let t = 400;
    if (!skipRiffle && !reduce) for (let k = 0; k < 2; k++) {
      later(t, () => { phase = 'split'; render(); }); t += 650;
      later(t, () => { phase = 'riffle'; order = riffle(order); render(); }); t += 1000;
      later(t, () => { phase = 'stack'; render(); }); t += 300;
    }
    later(t, () => { phase = 'flow'; A = reduce ? order.slice(0, P.N/2) : order.slice(); B = reduce ? order.slice(P.N/2) : [];
      render(); opts.onHint('flowing'); opts.onBusyChange(false); });
    if (!reduce) later(t + 650, () => { flowTimer = setInterval(step, P.FLOW); });
  }
  return {
    start,
    drawNow: () => pick(last ?? A[A.length - 1]),                          // כפתור "שליפת קלף"
    destroy: () => { timers.forEach(clearTimeout); clearInterval(flowTimer); }
  };
}
```

### 7.7 נגישות ומקלדת
- כפתור "שליפת קלף" הוא הדרך העיקרית לשלוף. ההקשה על קלף היא תוספת.
- שורת הסטטוס נמצאת ב־`aria-live="polite"`, וכל הטקסטים שלה מגיעים מסעיף 6.4.
- כל הקלפים המונפשים הם `<button>` עם `aria-label="קלף"`. Tab עובר ביניהם רק בשלב `flow`. בשאר הזמן יש להם `tabindex="-1"`.
- אחרי החשיפה הפוקוס עובר לכפתור "להמשך הקריאה".

### 7.8 תנועה מופחתת (`prefers-reduced-motion: reduce`)
- **בלי ריפל ובלי זרימה.** מוצגות שתי ערימות סטטיות, והכפתור מופעל מיד.
- **אחרי השליפה:** הקלף מופיע ישר במצב הסופי (לרוחב, התמונה מלאה), עם `opacity` של 0→1 ב־200ms.

### 7.9 בדיקות לשלב הזה
- [ ] הכפתור מושבת בזמן הריפל ומופעל כשמתחילה הזרימה.
- [ ] ברגע השליפה הכפתור "שליפת קלף" נעלם. אין רגע שבו הקלף כבר מוצג והכפתור עדיין שם.
- [ ] הזרימה מחליפה כיוון כשהערימה מתרוקנת, ולא נתקעת.
- [ ] לחיצה בכל רגע בזמן הזרימה שולפת את הקלף שבתנועה.
- [ ] הקשה על קלף באמצע הערימה שולפת אותו.
- [ ] התמונה **מגיעה מהשרת**. ב-Network רואים בקשה אחת ברגע השליפה, ובקוד ה-JS אין רשימת תמונות.
- [ ] הקלף מתהפך כשהוא עומד, ורק אחר כך מסתובב לרוחב. התמונה ישרה וממלאת את כל הקלף.
- [ ] הקלף הנבחר לא מכסה את הערימות. הן זזות הצידה ולמטה.
- [ ] כשהשרת מחזיר שגיאה, מופיעה שורת "ניסיון חוזר", הזרימה ממשיכה **וכפתור "שליפת קלף" חוזר**. (לבדוק עם הדמיית שגיאה, למשל בכיבוי הרשת ב-DevTools.)
- [ ] ברגע השליפה נעלמים גם הכפתור וגם שורת ההנחיה, בלי השהייה.
- [ ] הטקסטים הם בדיוק אלה שבסעיף 6.4: הכפתור "שליפת קלף" (לא "בחר קלף"), וההנחיה בלשון הפנייה.
- [ ] בטלפון (רוחב 360–430px) הכול נכנס בלי גלילה אופקית.
- [ ] עם תנועה מופחתת אין אנימציות.
- [ ] בעזיבת המסך כל ה־timers מתנקים (`destroy`).

## 8. מה **לא** עושים בשלב הזה
- לא בונים את "האזור שלי", לא את מסך המסלולים ולא חיבור סליקה.
- **חלון ההרשמה בתשלום מבוטל זמנית לנסיינים** (דגל הגדרה, למשל `KB_PAYWALL_ENABLED = false`).
- לא משנים את ה-prompts של ה-AI, חוץ מהסרת ההזמנה ללחוץ על "להמשיך ולהעמיק בשיחה" (סעיף 6.6).
