# הקורא בקלפים · מסמך הנחיות עיצוב ל־Claude Code

> **למי המסמך:** ל־Claude Code שמיישם את העיצוב החדש בתוסף הוורדפרס "הקורא בקלפים".
> **מקור:** הדמיית העיצוב שאושרה (לשונית "כיוון בהיר"). צילומי מסך מההדמיה יצורפו לכל שלב.
> **היקף השלב הזה:** עיצוב בלבד. לא משנים את הלוגיקה של ה-AI, לא נוגעים בתשלומים, ולא מוסיפים אזור אישי.

---

## 0. כללי עבודה (חובה לקרוא לפני כל שלב)

1. **עובדים בשלבים** (סעיף 9). בכל שלב: קודם מציגים תוכנית קצרה ומחכים לאישור, אחר כך משנים קוד, ובסוף עושים commit עם הודעה ברורה.
2. **לא משנים התנהגות קיימת** מעבר למה שכתוב כאן: חיבור ל-AI, התאמת לשון זכר/נקבה, שליחת מייל (בצד השרת), מגבלת 3 קלפים, הקלטה קולית ומשוב אגודל.
3. **RTL מלא:** `dir="rtl"` ו־`lang="he"`. משתמשים ב־logical properties (`margin-inline-start` וכו') ולא ב־left/right, חוץ מבאנימציות.
4. **לשון פנייה:** כל טקסט שמופיע כאן בשתי גרסאות (נ׳ / ז׳) נבחר לפי מה שהמשתמש סימן בחלון "נעים להכיר". לפני שהמשתמש בחר, משתמשים בלשון רבים.
5. **רספונסיביות:** נקודת שבירה אחת, **`1024px`**. מתחתיה פריסת טלפון, ומעליה פריסת מחשב.
   - **אסור שתהיה גלילה אופקית בעמוד, בשום מסך, וגם לא אחרי גלילה למטה.** (בדיקה: לגלול לתחתית מסך השיחה בטלפון, ולנסות לגרור את הדף הצידה. הוא לא אמור לזוז.) אם אלמנט כלשהו (במת הערבוב, ערימות הקלפים, כפתור ×) רחב מהמסך, הדף כולו זז הצידה, והלוגו והכפתורים נחתכים. על השורש: `.kb-app { overflow-x: clip; max-width: 100vw; }`. בבמת הערבוב בטלפון: הערימות **בתוך** רוחב המסך (`PX` מחושב מהרוחב בפועל: `PX = min(112, (stageWidth - CW) / 2 - 8)`), וכפתור × בתוך המסך, בפינה, עם 12px מהקצה.
   - חובה שיהיה בעמוד `<meta name="viewport" content="width=device-width, initial-scale=1">`.
6. **נגישות:**
   - כפתורים אמיתיים (`<button>`) וקישורים אמיתיים (`<a href>`).
   - לכל כפתור שיש בו רק אייקון יש `aria-label`.
   - פוקוס מקלדת גלוי (`outline: 3px solid var(--bordeaux); outline-offset: 3px`).
   - יעד לחיצה של 44×44px לפחות.
   - כבוד ל־`prefers-reduced-motion` (סעיף 7.8).
   - התוסף הקיים לנגישות נשאר.
7. **בלי ספריות חדשות** לאנימציה. CSS transitions ו־JavaScript רגיל מספיקים.
8. **מזהים ייחודיים:** כל ה-CSS של העיצוב החדש נכתב תחת קידומת אחת, `.kb-` (קיצור של "הקורא בקלפים"), כדי לא להתנגש בתבנית הוורדפרס.

## 1. צבעים (CSS variables)

```css
.kb-app {
  --paper:        #FBF8F6; /* רקע כללי */
  --surface:      #FFFFFF; /* תיבות, כרטיסים, מסגרת קלף */
  --ink:          #2A2326; /* טקסט ראשי */
  --ink-soft:     #4A3F43; /* טקסט גוף משני */
  --muted:        #6E6266; /* טקסט עזר, תוויות קטנות */
  --line:         #E6DCDE; /* קווי הפרדה, מסגרות עדינות */
  --line-strong:  #D9C9CD; /* מסגרת שדות קלט וכפתור משני */
  --bordeaux:     #7D2E46; /* צבע מוביל: כפתור ראשי, לוגו, הדגשות */
  --bordeaux-hover:#692539;
  --blush:        #F3E7EA; /* רקע עדין: בועת משתמש, כפתור מיקרופון, אזור "רוצה להעמיק?" */
  --dashed:       #C9AEB6; /* מסגרת מקווקוות של "קלף נוסף" */
  --scrim:        rgba(42,35,38,0.45); /* רקע כהה מאחורי חלונות */
  --shadow-card:  0 18px 40px rgba(42,35,38,0.16);
  --shadow-small: 0 4px 10px rgba(42,35,38,0.16);
}
```

**כללים:**
- **צבע מוביל אחד, בורדו.** אין אדום בוהק, אין שחור ואין אפור כהה בכפתורים.
- **טקסט לבן מופיע רק על בורדו.**
- **בלי גרדיאנטים בכלל**, והרקע אחיד בצבע `--paper`.
- **כפתור הנגישות של התוסף החיצוני:** לשנות את צבעו ל־`#7D2E46` בהגדרות התוסף. זה לא בקוד שלנו.

## 3. רכיבים

### 3.1 כפתורים (ארבעה סוגים בלבד)

```css
.kb-btn { font-family: 'Rubik', sans-serif; font-weight: 500; border-radius: 999px; min-height: 44px; padding: 0 22px; cursor: pointer; }
.kb-btn--primary   { background: var(--bordeaux); color: #fff; border: none; }            /* פעולה ראשית אחת במסך */
.kb-btn--primary:hover { background: var(--bordeaux-hover); }
.kb-btn--secondary { background: var(--surface); color: var(--ink); border: 1.5px solid var(--line-strong); }
.kb-btn--emphasis  { background: var(--surface); color: var(--bordeaux); border: 2px solid var(--bordeaux); } /* "שאלה חדשה" */
.kb-btn--link      { background: none; border: none; color: var(--bordeaux); font-weight: 400; text-decoration: underline; text-underline-offset: 4px; padding: 0 6px; } /* "לתת משוב": משקל רגיל, אייקון בקו בלבד */
.kb-btn:disabled   { background: var(--line); color: var(--muted); border: none; cursor: default; }
/* מצבי ריחוף ולחיצה: עדינים בלבד. אף כפתור לא נצבע בוורוד או באדום, בשום מצב */
.kb-btn--secondary:hover, .kb-btn--emphasis:hover { background: var(--blush); }
.kb-btn--link:hover { color: var(--bordeaux-hover); }
.kb-btn:active { transform: translateY(1px); }
/* כפתורי המסלול במסך הבית: אותם צבעים בכל מצב. לחיצה לא צובעת אותם באדום של התבנית */
.kb-app .kb-mode--primary, .kb-app .kb-mode--primary:hover, .kb-app .kb-mode--primary:focus, .kb-app .kb-mode--primary:active { background: #7D2E46 !important; color: #fff !important; border: none !important; }
.kb-app .kb-mode--secondary, .kb-app .kb-mode--secondary:focus, .kb-app .kb-mode--secondary:active { background: #FFFFFF !important; color: #7D2E46 !important; border: 1.5px solid #7D2E46 !important; }
.kb-app .kb-mode--secondary:hover { background: var(--blush) !important; }
```
- כפתור ראשי גדול: גובה 56px וגודל טקסט 18px.
- **"ביטול" בחלונות הוא תמיד כפתור שקט:** טקסט בצבע `--muted`, בלי רקע ובלי מסגרת. **אסור** שיהיה מלא או צבעוני.
- **לנטרל את עיצוב הכפתורים של התבנית:** כל כפתור של האפליקציה מקבל את המחלקה `.kb-btn`, וב-CSS שלנו מאפסים לפניה את ה־`background`, ה־`color` וה־`border` שמגיעים מהתבנית, כולל מצבי `:hover`, `:focus` ו־`:active`.
- **לכל כפתור יש מסגרת**, חוץ מהכפתור הראשי (מלא) והקישור "לתת משוב". "שליחת השיחה במייל" ו"סיום השיחה" הם `--secondary`: מסגרת דקה `1.5px solid var(--line-strong)`, רקע לבן וטקסט כהה (`--ink`), **לא** בורדו ולא טקסט בלי מסגרת.
- כל האייקונים בממשק הם קו בלבד (stroke) ברוחב 1.7–1.8, בלי מילוי ובלי אימוג'י.
- **כפתורי בחירת המסלול במסך הבית** הם כפתורים מלבניים עם פינות 18px, ובהם שתי שורות (שם ותיאור). ראו סעיף 6.3.

### 3.2 שדות קלט ותיבת טקסט עם מיקרופון
- רקע לבן, מסגרת `1.5px solid var(--line-strong)`, פינות 14–20px וטקסט 17–18px.
- **אין ידית לשינוי גודל:** `resize: none`.
- כפתור המיקרופון: עיגול 44px, רקע `--blush` ואייקון בבורדו. הוא יושב בתוך התיבה, בפינה התחתונה בצד שמאל.
- **כפתור שליחה** (במסך השיחה): עיגול 44px, רקע בורדו וחץ לבן שמצביע שמאלה, 20px (סעיף 3.2א).
- לכל שדה יש `<label>` גלוי מעליו, למשל "השאלה שלך" או "התשובה שלך".
- **פוקוס בשדות טקסט:** מסגרת אחת בלבד. במצב פוקוס המסגרת עצמה משתנה ל־`2px solid var(--bordeaux)`, עם הילה רכה `box-shadow: 0 0 0 3px rgba(125,46,70,.12)`, **בלי `outline` נוסף**, כדי שלא תיווצר מסגרת כפולה. אותו מראה בדיוק בכל השדות ובכל המצבים (מסר ודיאלוג).

### 3.2א אייקונים: גודל קבוע ותמיד SVG
- **כל אייקון הוא `<svg>` שמוטמע ישירות ב-HTML**, עם `width` ו־`height` **גם כמאפיינים וגם ב־CSS**. לא פונט אייקונים, לא תמונה ולא אימוג'י.
- **תבניות וורדפרס נוטות להקטין או למתוח SVG** (כללים כמו `svg { max-width: 100% }` או `button svg { width: 1em }`). לכן מגדירים מחלקה ייעודית עם עדיפות גבוהה:
```css
.kb-app .kb-icon { width: 20px !important; height: 20px !important; min-width: 20px; flex: none; display: block; }
.kb-app .kb-icon--sm { width: 18px !important; height: 18px !important; min-width: 18px; }
.kb-app .kb-icon-btn { width: 44px; height: 44px; min-width: 44px; padding: 0; display: inline-flex; align-items: center; justify-content: center; font-size: 0; line-height: 0; }
```
- **גדלים:** בכפתורים העגולים (שליחה, מיקרופון, ☰) האייקון 20px בתוך עיגול של 44px. אגודלים: 18px בתוך אזור לחיצה של 38–40px.
- **כפתור השליחה כשהתיבה ריקה:** מושבת, רקע `--line` וחץ בצבע `--muted`, **באותו גודל** כמו במצב הפעיל.

### 3.3 קלף
| מצב | צורה | פרטים |
|---|---|---|
| **גב קלף** (בחפיסה) | **עומד** (יחס 2:3) | רקע בורדו, מסגרת לבנה 3px, פינות 12–14px, קו פנימי דק `rgba(243,231,234,.5)` במרחק 6–8px מהקצה, וסמל הלוגו (סעיף 4) במרכז בצבע `#F3E7EA` |
| **קלף שנשלף** (מסך הקריאה ומסך המסר) | **לרוחב** (יחס 4:3) | מסגרת לבנה 8–12px, פינות 14–16px, `box-shadow: var(--shadow-card)`, והתמונה **ממלאת את כל הקלף** (`object-fit: cover`) עם פינות 7–8px. הטיה קלה של ‎-1.5° עד ‎+1.5°, שונה לכל קלף |

**חשוב:** תמונות מהחפיסה לא מופיעות בשום מקום אחר באפליקציה, כולל מסך הבית ודף הכניסה. שם משתמשים רק בגבי קלפים, **ותמיד עומדים** (2:3), לעולם לא לרוחב. רק קלף שנשלף ונחשף מוצג לרוחב.

### 3.4 חלונות קופצים (bottom sheet בטלפון, modal במחשב)
- **רקע:** `--scrim`.
- **בטלפון:** גיליון שעולה מלמטה, ברוחב מלא, עם פינות עליונות של 28px, רקע `--paper`, ידית קטנה למעלה (44×5px, `--line`) וריווח פנימי `14px 24px 34px`.
- **במחשב:** חלון במרכז המסך ברוחב מקסימלי 520px, עם פינות 24px.
- **מבנה קבוע:** כותרת, משפט הסבר קצר, שדות, כפתור ראשי אחד, ומתחתיו כפתור משני שקט ("ביטול").
- **סגירה:** ב־Esc, בלחיצה על הרקע ובכפתור "ביטול". הפוקוס נשאר כלוא בתוך החלון ונעבר לשדה הראשון כשהחלון נפתח.
- **אסור** להשתמש ב־`window.prompt` או ב־`window.alert`. החלון האפור של הדפדפן, "staging... says", יוצא לגמרי.

### 3.5 הודעות בשיחה
- **הודעת AI:** **בלי בועה.** מעל הטקסט מופיעה שורה קטנה: עיגול 34px ברקע `--blush` עם סמל הלוגו, והמילה "הקורא" בגודל 15px בצבע `--muted`. מתחתיה הטקסט ב־19px עם גובה שורה 1.8, ופסקאות נפרדות.
- **אגודל למעלה ולמטה:** **אותו SVG בדיוק בשניהם.** באגודל למטה מסובבים את כל ה-SVG (`transform: rotate(180deg)`). לא משתמשים בצורה אחרת ולא בהיפוך מראה. סדר: אגודל למעלה מימין, אגודל למטה משמאל. שני כפתורי אייקון שקטים מתחת להודעת ה-AI. גודל 36–40px, קו דק בצבע `--muted`, בלי רקע ובלי אימוג'י. **במצב נבחר:** העיגול מתמלא בבורדו (`--bordeaux`) והאייקון הופך ל**לבן**. רק אגודל אחד יכול להיות נבחר בכל רגע.
```css
.kb-app .kb-thumb { width: 38px; height: 38px; border-radius: 50%; border: 0; background: transparent !important; color: var(--muted); }
.kb-app .kb-thumb svg { stroke: currentColor !important; fill: none !important; }
.kb-app .kb-thumb[aria-pressed="true"],
.kb-app .kb-thumb[aria-pressed="true"]:hover,
.kb-app .kb-thumb[aria-pressed="true"]:focus { background: #7D2E46 !important; color: #FFFFFF !important; }
.kb-app .kb-thumb:hover:not([aria-pressed="true"]) { background: var(--blush) !important; }
```
(הוורוד שרואים היום הוא צבע הכפתורים של התבנית. הכללים האלה דורסים אותו.)
- **הודעת משתמש:** בועה בצבע `--blush` עם טקסט כהה, פינות `20px 20px 20px 6px`, מיושרת לצד שמאל (סוף השורה ב־RTL) וברוחב מקסימלי של 75%.
- **הודעת שגיאה:** **לא** מופיעה כבועה. היא מוצגת כשורת התראה מתחת לשיחה, עם רקע `--blush`, פינות 14px, ריווח `12px 16px` וטקסט 15px:
  > החיבור נקטע לרגע. ההודעה שלך לא אבדה.  **[ניסיון חוזר]**

  "ניסיון חוזר" שולח שוב את ההודעה האחרונה. אם גם הניסיון השני נכשל, מוסיפים את הכפתור "שאלה חדשה". על הודעת שגיאה אין אגודלים.

### 3.5א שגיאות ואימות שדות (כלל: אין חלונות של הדפדפן)

**אסור בשום מקום באפליקציה:** `alert()`, `confirm()` ו־`prompt()`. כל הודעה מופיעה בתוך הממשק, ליד המקום שבו היא רלוונטית.

**שלושה סוגי הודעות, ולא יותר:**

| סוג | מתי | איך נראה |
|---|---|---|
| **שגיאת שדה** | שדה ריק או לא תקין | מסגרת השדה הופכת ל־`2px solid var(--error)`. מתחת לשדה מופיעה שורה של 14px בצבע `--error`, עם אייקון עיגול-סימן-קריאה קטן (16px). השדה מקבל `aria-invalid="true"` ו־`aria-describedby` שמצביע על ההודעה, והפוקוס עובר אליו. ההודעה **נעלמת ברגע שמתחילים להקליד** |
| **שורת התראה** | תקלה בתקשורת עם השרת | לפי סעיף 3.5: רקע `--blush`, טקסט כהה וכפתור פעולה ("ניסיון חוזר") |

## 4. לוגו: מניפה של שלושה קלפים

```html
<svg width="30" height="26" viewBox="0 0 40 34" fill="#FBF8F6" stroke="#7D2E46" stroke-width="2"
     stroke-linejoin="round" aria-hidden="true">
  <rect x="14" y="5" width="12" height="18" rx="2" transform="rotate(-24 20 31)"/>
  <rect x="14" y="5" width="12" height="18" rx="2" transform="rotate(24 20 31)"/>
  <rect x="14" y="3" width="12" height="18" rx="2"/>
  <circle cx="20" cy="12" r="1.6" fill="#7D2E46" stroke="none"/>
</svg>
```
- **הסמל תמיד חלול: קו בלבד.** אסור למלא אותו בצבע הקו, כי בגדלים קטנים הוא הופך לכתם.
- **`fill` הוא תמיד צבע הרקע שמתחת לסמל** (לא צבע הקו!), כדי שהקלף הקדמי יסתיר את הקווים שמאחוריו ויישאר חלול:
  - על הרקע הכללי: `#FBF8F6`
  - בתוך עיגול ורדרד: `#F3E7EA`
  - על גב קלף בורדו: `fill="#7D2E46"` עם `stroke="#F3E7EA"`, ובמקרה הזה גם העיגול הקטן בצבע `#F3E7EA`.
- גדלים: 30px בכותרת במחשב, 26px בטלפון, 17–19px באוואטר של ה-AI (שם `stroke-width` 2.4 ו־`fill="#F3E7EA"`), ו־40–64px על גב קלף.

## 5. תפריט ☰
- **בטלפון:** מסך מלא ברקע `--paper`, עם כפתור × לסגירה.
- **במחשב:** פאנל שנפתח מצד שמאל, ברוחב 380px, עם רקע `--scrim` מאחוריו.
- **פריטים ראשיים** (גובה 56px, טקסט 18px, אייקון בבורדו מימין וקו הפרדה `--line` בין הפריטים):
  1. איך זה עובד. חלון עם חמישה שלבים ממוספרים:
     1. **כותבים שאלה.** על משהו שמעסיק אתכם עכשיו: עבודה, קשרים, החלטה, הרגל.

     3. **שולפים קלף.** הקלפים מתערבבים, ואתם בוחרים קלף אקראי.
     4. **מקבלים תשובה.** הקורא בקלפים מכוון אתכם לתשובה המדויקת עבורכם.
     5. **ממשיכים לשוחח.** בדיאלוג המכוון מתפתחת שיחה של שאלות ותשובות שמעוררות מחשבה.
  2. טיפים לשאלה טובה (התוכן של "הנחיות" הנוכחי)
  3. אודות
  4. כתבו לנו (הטופס הקיים)

|---|---|
| מעל השאלה (15–16px) | השאלה שלך |
| השאלה | (הטקסט שהמשתמש כתב). **בטלפון:** 18px, עד 3 שורות. אם השאלה ארוכה יותר, היא נחתכת עם …, והקשה עליה פותחת וסוגרת אותה. בשום מקרה היא לא דוחקת את הקלפים מתחת לקצה המסך |
| מתחת לקלפים, כל הזמן | נ׳: התחלתי לערבב. כשמרגיש לך נכון, געי באחד הקלפים. / ז׳: התחלתי לערבב. כשמרגיש לך נכון, גע באחד הקלפים. |
| כפתור | **שליפת קלף**, פעיל **מהרגע הראשון** (אין מצב "רגע, מערבבים…"). כפתור משני, שקט, מתחת לטקסט. הוא קיים בשביל נגישות (מקלדת וקורא מסך): לחיצה עליו זהה לנגיעה בקלף |
| אחרי החשיפה | נ׳: זה הקלף הנבחר. קחי רגע להתבונן ולחשוב על השאלה שלך / ז׳: זה הקלף הנבחר. קח רגע להתבונן ולחשוב על השאלה שלך |
| כפתור אחרי החשיפה | להמשך הקריאה |

### 6.5 מסך דיאלוג מכוון
- **זה מסך נפרד, לא המשך של מסך הבית.** ברגע שהשאלה נשלחה, **כל חלק מסך הבית נעלם**: הברכה, הכותרת "מה מעסיק אותך היום?", הפסקה, תיבת השאלה, כפתורי המסלול וגבי הקלפים הדקורטיביים. **אין** תווית "זה הקלף שנבחר", **ואין** בועה "שאלת: …", כי השאלה כבר מוצגת.
- **מבנה של אפליקציית צ'אט:** המסך תופס בדיוק את גובה החלון (`height: 100dvh`). **השאלה והקלפים קבועים** ולא נגללים, **רק השיחה נגללת**, ו**תיבת התשובה קבועה בתחתית**. המשתמש אף פעם לא צריך לגלול הלוך וחזור כדי לראות את התמונה או להגיע לתיבה.

**במחשב (מעל 1024px): שתי עמודות**
```
┌──────────────────────────────── header ────────────────────────────────┐
│ ┌──── עמודת צד (380px, ימין) ────┐ ┌──────── עמודה רחבה ─────────────┐ │
│ │ הקלפים שלך                     │ │ השאלה שלך (קבועה, מלאה, 24px)    │ │
│ │ [קלף 1, לרוחב]                 │ ├──────────────────────────────────┤ │
│ │ [קלף 2]                        │ │  ↕ ההודעות נגללות (עד 680px)     │ │
│ │ צריך עוד קלף?                  │ │                                  │ │
│ │ ───────────                    │ ├──────────────────────────────────┤ │
│ │ [שאלה חדשה]                    │ │  תיבת התשובה                     │ │
│ │ [שליחת השיחה במייל]            │ └──────────────────────────────────┘ │
│ │ [סיום השיחה]   לתת משוב         │                                      │
│ └────────────────────────────────┘                                      │
└─────────────────────────────────────────────────────────────────────────┘
```
- **השאלה נמצאת בראש העמודה הרחבה, לא בעמודת הצד.** היא מוצגת **במלואה**: בלי חיתוך, בלי גלילה פנימית ובלי `line-clamp`, גם כשהיא ארוכה. 24px, משקל 500, צבע `--ink`, ומעליה "השאלה שלך" (14px, `--muted`). היא **קבועה** בראש העמודה, ההודעות נגללות מתחתיה, ומתחתיה קו `--line`.
- **עמודת הצד** (380px, מימין, עם קו הפרדה `--line`): "הקלפים שלך" (14px, `--muted`), הקלפים זה מתחת לזה (לרוחב, באותו גודל) והקישור "צריך עוד קלף?". **מיד אחרי הקלפים**, עם רווח של 24px, באים כפתורי הפעולות. הכפתורים **לא** מוצמדים לתחתית העמודה, ולכן אין חלל ריק לפניהם. הם מסודרים **אחד מתחת לשני, כל אחד ברוחב מלא של העמודה** (`width: 100%`), ו"לתת משוב" ממורכז מתחתיהם. אם התוכן גבוה מהחלון, **העמודה נגללת**, ושום כפתור לא נחתך.
- **העמודה הרחבה:** בראשה השאלה, מתחתיה ההודעות ברוחב קריאה של עד 680px, ובסוף תיבת התשובה. **תיבת התשובה צמודה להודעה האחרונה** כל עוד השיחה קצרה, ולא נזרקת לתחתית המסך. רק כשהשיחה ממלאת את הגובה, ההודעות נגללות והתיבה נשארת קבועה בתחתית. מבחינה טכנית: העמודה היא `display:flex; flex-direction:column`, השאלה `flex: none`, אזור ההודעות `flex: 0 1 auto; min-height: 0; overflow-y: auto`, והתיבה `flex: none`.
- **גובה המסך, כדי שהתיבה לעולם לא תיחתך:** התבנית מוסיפה מעל האפליקציה מרווחים, ולפעמים גם סרגל ניהול, ולכן אי אפשר לנחש את הגובה ב-CSS בלבד. מחשבים אותו ב-JS: `container.style.height = (window.visualViewport?.height ?? innerHeight) - container.getBoundingClientRect().top + 'px'`, ומעדכנים ב־`resize` וב־`visualViewport.resize`. **לבדוק ב־1366×768, ב־1920×1080 ובזום דפדפן של 125%.** בכל המצבים התיבה וכפתוריה גלויים במלואם בלי לגלול את העמוד.

**בטלפון: כל פיקסל לשיחה**
המטרה: לפחות **60% מגובה המסך** לשיחה עצמה. לכן:
- **כותרת עליונה מצומצמת:** גובה 52px. הלוגו 22px, השם 16px וכפתור ☰ של 40px. **בלי ריווח מעל הכותרת:** לבטל את ה־`padding`/`margin` העליון שהתבנית מוסיפה לעמוד של האפליקציה.
- **רצועה אחת קבועה, בגובה של כ־80px:** מימין **תמונות ממוזערות** של הקלפים (64×48px, מסגרת לבנה 2px), **ומתחתיהן הקישור "צריך עוד קלף?"** (12px, `--muted`, קו תחתון), כדי שיהיה זמין תמיד בלי לגלול. משמאל לתמונות **השאלה**: 15px, משקל 500, **עד 2 שורות**, וחץ קטן ⌄ בסופה.
  - **בלי כותרות** "השאלה שלך" ו"הקלפים שלך". ברור מההקשר מה הם.
  - **השאלה מודגשת בתיבה עדינה:** רקע `--blush` (#F3E7EA), פינות 12px, ריווח `8px 10px`. כך ברור שזו השאלה של המשתמש. **התיבה ממורכזת אנכית מול התמונה הממוזערת** (`align-self: center`), ולא מיושרת לראש הרצועה.
  - **"צריך עוד קלף?" צמוד לתמונה:** ממש מתחתיה (2px), **מיושר לקצה הימני של התמונה** (`text-align: start`, בלי מרכוז), בלי רווח ובלי קו ביניהם. הקצה הימני של הטקסט והקצה הימני של התמונה על אותו קו.
  - **הקשה על השאלה פותחת אותה במלואה, והקשה נוספת סוגרת אותה.** החץ מתהפך, ו־`aria-expanded` מתעדכן.
  - **הקשה על תמונה ממוזערת פותחת את הקלף בגדול**, בשכבה מעל המסך (רקע `--scrim`, הקלף ברוחב המסך, וסגירה בהקשה או ב־×).
- **תיבת התשובה:** **שורה אחת** בהתחלה (גובה כ־48px), שגדלה עם הטקסט עד 5 שורות. המיקרופון וכפתור השליחה (40px כל אחד) **בתוך** התיבה. התווית "התשובה שלך" מוסתרת ויזואלית (`sr-only`). placeholder קצר: נ׳ "כתבי מה עולה בך…" / ז׳ "כתוב מה עולה בך…".
- **כשהמקלדת נפתחת, התיבה וכפתוריה נשארים גלויים במלואם, צמודים למקלדת:**
  1. בתגית ה-viewport מוסיפים `interactive-widget=resizes-content`: `<meta name="viewport" content="width=device-width, initial-scale=1, interactive-widget=resizes-content">`. בכרום לאנדרואיד זה גורם לדף להתכווץ כשהמקלדת נפתחת, במקום שהמקלדת תכסה אותו.
  2. גיבוי ב-JS (לספארי באייפון ולדפדפנים אחרים): מאזינים ל־`visualViewport.resize`, מגדירים לאפליקציה גובה של `visualViewport.height - top`, ואז `window.scrollTo(0, 0)`. כך הרצועה העליונה, השיחה והתיבה נכנסים כולם בחלק הגלוי.
  3. **כשהמקלדת פתוחה, מפנים מקום לשיחה:** מזהים את המצב לפי `visualViewport.height < window.innerHeight * 0.75`, ומוסיפים לאפליקציה מחלקה `kb-kbd-open`. במצב הזה:
     - הרצועה העליונה מצטמצמת לשורה אחת: השאלה בשורה אחת עם …, תמונה ממוזערת 40×30, ו"צריך עוד קלף?" מוסתר.
     - תיבת התשובה גדלה עד 3 שורות בלבד (לא 5).
     - **לפחות 3 שורות מההודעה האחרונה של הקורא גלויות** מעל התיבה. אם לא, משהו עדיין גבוה מדי.
  4. **לבדוק בטלפון אמיתי:** פותחים מקלדת וכותבים 3 שורות. המיקרופון וכפתור השליחה גלויים במלואם, וההודעה האחרונה נקראת מעל התיבה.
- **כפתורי הפעולות ו"לתת משוב" הם תמיד הדבר האחרון במסך, מתחת לתיבת התשובה.** הסדר בטלפון, מלמעלה למטה:
  1. הרצועה (קבועה בראש המסך בזמן גלילה, `position: sticky; top: 0`)
  2. ההודעות
  3. תיבת התשובה
  4. **כפתורי הפעולות ו"לתת משוב"**
  - **לכן בטלפון העמוד כולו נגלל**, ואין גלילה פנימית באזור ההודעות. תיבת התשובה **לא** קבועה בתחתית: היא באה מיד אחרי ההודעה האחרונה, והכפתורים מתחתיה.
  - **אחרי כל הודעה חדשה**, העמוד גולל כך ש**תיבת התשובה נמצאת בתחתית המסך** וההודעה החדשה מעליה. הכפתורים נשארים ממש מתחת לקצה המסך, ומגיעים אליהם בגלילה קצרה.
  - **כשהמקלדת נפתחת**, התיבה נגללת לתוך המסך (`scrollIntoView({block: 'end'})`).
  - **מעבר ממסר לדיאלוג מכוון, ובכל פעם שהקורא שואל שאלה:** העמוד גולל כך ש**תיבת התשובה נראית בתחתית המסך**, ומעליה שאלת הקורא, ומעליה כמה שנכנס מהמסר. המשתמש צריך להבין מיד שעכשיו תורו לענות, בלי לגלול.
  - **השאלה הפתוחה של הקורא מודגשת (בטלפון וגם במחשב):** ההודעה האחרונה של הקורא, כל עוד המשתמש לא ענה עליה, במשקל 500. כשהמשתמש שולח תשובה, היא חוזרת למשקל רגיל.
  - **אין `autofocus` על תיבת התשובה, אף פעם.** גם לא אחרי מעבר ממסר לדיאלוג מכוון ולא אחרי תשובה של הקורא. המקלדת נפתחת רק כשהמשתמש נוגע בתיבה. אחרי המעבר לדיאלוג, המשתמש רואה קודם את המסר ואת שאלת הקורא, ומתחתיהן את התיבה עם המיקרופון.
  - **קובץ הפניה:** `docs/mobile-reading-reference.html` מראה את המבנה המדויק בטלפון. לפתוח אותו בדפדפן ברוחב 390 ולהשוות.
  - **במצב מסר** הסדר לפי סעיף 6.6: המסר, האגודלים, "רוצה להעמיק?", הכפתורים.
  - בזמן שהקורא כותב, הכפתורים נשארים במקומם, אבל "צריך עוד קלף?" מוסתר וכפתור השליחה מושבת (ראו "המתנה לתשובה").
- הודעות ה-AI בטלפון: 16px, גובה שורה 1.7.

**המתנה לתשובה מהקורא: המסך אף פעם לא ריק.**
- **מיד** כשהקלף נוחת (וגם אחרי כל הודעה של המשתמש), מופיעה בעמודה הרחבה שורת "הקורא" עם **סימן הקלדה**: שלוש נקודות של 6px בצבע `--muted`, שמהבהבות בזו אחר זו. לידן טקסט שקט (15px, `--muted`):
  - לפני התשובה הראשונה: "הקורא מתבונן בקלף ובשאלה שלך…"
  - בהמשך השיחה: "הקורא כותב…"
- כשהתשובה מגיעה, היא מחליפה את השורה הזו באותו מקום, בלי קפיצה.
- אם עוברות 20 שניות בלי תשובה, השורה מתחלפת בשורת השגיאה מסעיף 3.5, עם "ניסיון חוזר".
- **בזמן שהקורא כותב, אי אפשר לשלוף קלף נוסף ואי אפשר לשלוח הודעה:** הקישור "צריך עוד קלף?" מוסתר, וכפתור השליחה מושבת. (אפשר להמשיך להקליד בתיבה.) הם חוזרים ברגע שהתשובה מגיעה. כך תשובה אף פעם לא "מתנגשת" בקלף חדש.

**התנהגות הגלילה (בשתי הגרסאות):**
- כשמגיעה הודעה חדשה, אזור השיחה גולל אליה בעדינות, **אלא אם** המשתמש גלל למעלה כדי לקרוא הודעה קודמת. במקרה כזה לא קופצים, ומציגים כפתור קטן "↓ הודעה חדשה" מעל תיבת התשובה.
- **תיבת התשובה במחשב:** 3 שורות בהתחלה, גדלה עד כ־10 שורות.

- **"צריך עוד קלף?" מוצנע בכוונה.** זו אפשרות למקרים קיצוניים, ואנחנו לא רוצים לעודד אותה:
  - **קישור טקסט קטן בלבד**, בלי מסגרת, בלי קופסה ובלי אייקון +. 14px, צבע `--muted`, קו תחתון דק.
  - **מופיע רק אחרי שהמשתמש ענה לפחות פעם אחת בשיחה.** אין מונה, ואחרי הקלף השלישי הקישור נעלם.
- **קלף נוסף משתמש באותה אנימציה של סעיף 7,** בגרסה קצרה: בלי שלב הריפל, ישר לזרימה בין הערימות.
  - היא נפתחת כ**שכבה על כל המסך**, ברקע `--paper` (לא שקוף) ועם כפתור × לסגירה. **לא בתוך העמודה הרחבה ולא מעל השיחה.** כך האנימציה לא מתנגשת בטקסט.
  - **ריווח קבוע:** בין הבמה (כולל עובי הערימות) לשורת ההנחיה יש 24px, ובין ההנחיה לכפתור 16px. ההנחיה והכפתור לעולם לא עולים על הקלפים.
  - **מה הקורא כותב אחרי קלף נוסף:** הודעה **אחת בלבד**, שמתייחסת **לקלף החדש** במפורש ומחברת אותו לשיחה עד עכשיו. למשל: "שלפת קלף נוסף: מדרגות לולייניות. איך הוא מתחבר למה שאמרת קודם על…". **אסור** להציג את ההודעה "שלפת קלף נוסף…" פעמיים, ואסור שהתשובה תתייחס רק לקלף הקודם. בהנחיות של ה-AI (ה-prompt) צריך לכלול את תיאור הקלף החדש ואת ההוראה להתייחס אליו.
  - אחרי החשיפה: "להמשך הקריאה" סוגר את השכבה. הקלף מופיע בעמודת הצד (במחשב) או ברצועת התמונות הממוזערות (בטלפון), ומיד מופיע סימן ההקלדה של הקורא.

| רכיב | טקסט |
|---|---|
| שם השולח בהודעות ה-AI | הקורא |
| תווית תיבת התשובה | התשובה שלך (מוסתרת ויזואלית, `sr-only`, כי התיבה קבועה ומובנת מעצמה. נשארת לקוראי מסך) |
| placeholder | נ׳: כתבי מה עולה בך, או שאלי שאלת המשך / ז׳: כתוב מה עולה בך, או שאל שאלת המשך |
| קישור קלף נוסף | צריך עוד קלף? |
| כפתורי פעולות | **שאלה חדשה** (`--emphasis`) · שליחת השיחה במייל (`--secondary`) · סיום השיחה (`--secondary`) · **לתת משוב** (`--link` עם אייקון בועת דיבור). מחשב: בתחתית עמודת הצד, אחד מתחת לשני. טלפון: בסוף השיחה |

- מעל כפתורי הפעולות יש קו `1px solid var(--line)`.
- **"סיום השיחה" ו"שאלה חדשה" לא פותחים את חלון המשוב.**

### 6.6 מסך קבלת מסר אישי
- בראש המסך "השאלה שלך" והשאלה, ומתחתן **קלף אחד לרוחב**.
- אחר כך הודעת ה-AI עם הכותרת **"הקורא – המסר שלך ממני"** (באותו מבנה כמו "הקורא": אוואטר קטן משמאל לטקסט), והאגודלים.
- **אזור "רוצה להעמיק?"** (במקום הכפתור האפור "להמשיך ולהעמיק בשיחה"): קופסה ברקע `--blush`, פינות 18px וריווח 20px.
  | רכיב | טקסט |
  |---|---|
  | כותרת (19px) | רוצה להעמיק? |
  | הסבר (15px) | אפשר להמשיך מכאן לדיאלוג מכוון, עם אותה שאלה ואותו קלף. הקורא ישאל אותך שאלות ויעזור לך להגיע לתשובה מדויקת יותר. |
  | כפתור ראשי | המשך לדיאלוג מכוון |
- **במצב מסר אין תיבת תשובה בכלל.**
- **הסדר בעמודת השיחה (ובטלפון, בגלילה), מלמעלה למטה, בדיוק כך:**
  1. הודעת הקורא ("הקורא – המסר שלך ממני") **עם הטקסט המלא של המסר**
  2. האגודלים
  3. **האזור "רוצה להעמיק?"**, מיד אחרי המסר. זו הפעולה העיקרית במסך
  4. כפתורי הפעולות (שאלה חדשה, שליחה במייל, סיום השיחה)
  5. "לתת משוב"
- **לחיצה על "המשך לדיאלוג מכוון":**
  1. האזור "רוצה להעמיק?" נעלם.
  2. **הקורא כותב מיד הודעת פתיחה** לדיאלוג, ששואלת שאלה ראשונה. מבקשים אותה מה-AI (עם השאלה, הקלף והמסר שכבר ניתן), ועד שהיא מגיעה מוצג **סימן הקלדה**: שלוש נקודות קטנות בצבע `--muted` מתחת ל"הקורא". אם ה-AI לא עונה, משתמשים בטקסט קבוע: נ׳ "בואי נעמיק. מה הדבר הראשון שמשך את עינך בתמונה?" / ז׳ "בוא נעמיק. מה הדבר הראשון שמשך את עינך בתמונה?"
  3. **רק אחרי שהודעת הפתיחה מופיעה**, נפתחת תיבת התשובה. אף פעם לא מוצגת תיבה ריקה בלי שאלה מהקורא.
- ההודעה בסוף המסר שמזמינה ללחוץ על "להמשיך ולהעמיק בשיחה" **מיותרת עכשיו**. צריך להסיר אותה מהנוסח שה-AI מחזיר, או לסנן אותה בתצוגה.
- **שורת פעולות:** שאלה חדשה (`--emphasis`), שליחה במייל, סיום, ו"לתת משוב".

### 6.10 חלונות במקום הפופאפים של אלמנטור

**עיקרון:** האפליקציה לא פותחת יותר אף פופאפ של אלמנטור. כל החלונות הם `kb-modal` (סעיף 3.4), עם השם ולשון הפנייה מ־localStorage. את הפופאפים באלמנטור **לא מוחקים** בשלב הזה, רק מפסיקים לקרוא להם. אחרי שבוע של שקט מוחקים את הקוד המת: `openOnboardingPopup`, ההסתרה של 4723, השרשור של 4729, `openPopupById`, `forceClosePopupById`, מאזיני `submit_success`.

#### 6.10.1 הרשמה עם מייל (במקום 4749). הדמיה: "טלפון · הרשמה עם מייל"
- **מתי:** בדיוק במקומות שבהם נקרא היום `triggerRegistrationWall()`: משתמש אנונימי שנגמרו לו השימושים.
- **כותרת:** "{שם}, נמשיך?"
- **טקסט (של נורית, לא לשנות):** "אני ממש אוהב את השיחות שלנו, ואני יודע שהן עוזרות לך **לקבל תשובות ולהתקדם**. אני מזמין אותך להמשיך ולהשתמש באפליקציה." ובפסקה נפרדת: "רק נא למלא את הפרטים שלך, לצורכי בקרה ושיפור השירות." (הטקסט זהה לנ׳ ולז׳.)
- **שדות:** "שם" (ממולא מראש מ"נעים להכיר", **ניתן לשינוי**; שינוי מעדכן גם את localStorage, וממנו והלאה הקורא פונה בשם החדש) · "כתובת מייל" (`type=email`, `autocomplete=email`, `dir=ltr`). ולידציית השם כמו ב"נעים להכיר" (`DCARD_NAME_PATTERN`).
- **מתחת לשדות:** "לא נשלח לך דיוור שיווקי. המייל משמש רק לשמירת השימושים שלך."
- **כפתורים:** "אשמח להמשיך" (ראשי) · "לא עכשיו" (שקט, סוגר את החלון ולא עושה כלום נוסף).
- **שורה קטנה למטה:** לפי לשון הפנייה: "בהמשך אתה מאשר…" / "בהמשך את מאשרת…" / "בהמשך אתם מאשרים…", ואחריו "את [תנאי השימוש] ואת [מדיניות הפרטיות]." בלי תיבת סימון לדיוור. **בכל המסמך, "את/ה", "אלייך/אליך" וכדומה הם סימון לפנייה לפי מגדר, לא טקסט להצגה.**
- **שגיאת מייל או שם:** מסגרת השדה `2px #A3262A` ושורה מתחתיו (סעיף 3.5א). למייל: "הכתובת לא נראית תקינה. כדאי לבדוק שוב."
- **שרת:** נקודת קצה חדשה `POST /wp-json/dcard/v1/register` שקוראת ל־`DCard_Users::register_and_issue_device_token()` עם המייל, השם ולשון הפנייה, ומחזירה את אותם נתונים שה-hook של אלמנטור מחזיר היום (`userId`, `deviceToken`, `plan`, `credits`, `email`). מייל שכבר רשום: מחזירים את המשתמש הקיים (כמו היום), בלי הודעת שגיאה.
- **אחרי הצלחה:** וי, "נרשמת, אפשר להמשיך", ותוך שנייה החלון נסגר **והפעולה שנחסמה ממשיכה לבד** (הערבוב נפתח, או הקלף הנוסף).
- **ה-hook של אלמנטור (`on_new_record`) נשאר** בינתיים, כי יכול להיות שטפסים אחרים באתר משתמשים בו.

#### 6.10.2 חלון ההצטרפות למסלול (במקום 4753). הדמיה: "טלפון · הצטרפות למסלול"
- **מתי:** במקומות שבהם נקרא היום `triggerPaymentWall()`, כש"חלון התשלום פעיל" מסומן.
- **כותרת:** "{שם}, נמשיך יחד?"
- **טקסט (של נורית):** "אמרתי לך כבר קודם שאני אוהב שהשיחות שלנו **תומכות ועוזרות להתקדם בחיים**. יחד עם זה, כמו הרבה דברים בחיים, אני עולה כסף, ועד עכשיו נורית שילמה עליי." ובפסקה שנייה: "אני מזמין אותך להמשיך ולהשתמש באפליקציה, ואני **יודע מניסיון רב** שהשימוש ימשיך לתת לך ערך רב ולאורך זמן. בניתי שלושה מסלולים, ורק צריך לבחור את המתאים לך ביותר."
- **שמות המסלולים בחלון הם השמות החדשים:** "קבלת מסר" ו"דיאלוג מכוון" (לא "קבלת מסר יומי" ו"שיחה מפתחת" כמו בפופאפ הישן).
- **המסלולים מוצגים כרשימה פשוטה, לא כטבלה ולא ככרטיסים.** כותרת "המסלולים לבחירתך" (16px, 500). `<ul>` עם קו `--line` מעל, מתחת ובין הפריטים, בלי מסגרות, בלי רקע, בלי ריחוף. כל פריט שתי שורות:
  - שורה 1: שם המסלול (18px, 500) מימין, ומשמאל "**{מחיר} ₪** לחודש".
  - שורה 2 (15px, `--ink-soft`): "{N} קבלות מסר · {M} דיאלוגים מכוונים".
- **אין "ללא הגבלה" בכלל.** תמיד מציגים את המספר האמיתי (למשל "100 קבלות מסר · 80 דיאלוגים מכוונים"). כך אין כוכבית ואין הסבר מסתייג.
- מתחת לרשימה: "המכסה מתחדשת בכל חודש." (13px, `--muted`).
- **רק המייל, לתצוגה בלבד** (השם כבר מופיע בכותרת): תיבה ברקע `--blush` עם "המסלול יחובר לכתובת:" ומתחתיו הכתובת ב-`<bdi dir="ltr">`, משקל 500. **התווית בעברית ימנית, והכתובת בשורה נפרדת**, כדי שהכיווניות לא תהפוך את השורה. מתחת: "אם הכתובת שגויה, [כתבו לנו] ונשמח לעזור." **הקישור סוגר את חלון ההצטרפות ופותח את "כתבו לנו". הוא לא שולח טופס ולא עובר לקארדקום** (`type="button"`, `preventDefault`). הפנייה נשלחת עם המייל הרשום ומזהה המשתמש, ובנושא "– תיקון מייל".
- **כפתור ראשי:** "אשמח להירשם ולהמשיך". מתחתיו: "בחירת המסלול והתשלום בעמוד המאובטח של קארדקום." וכפתור שקט "אולי בפעם אחרת".
- **לחיצה:** אין מה לשמור (השם והמייל לא משתנים כאן), ישר מעבר **לכתובת קארדקום האחת** עם `ReturnValue=<userId>`, כמו היום. השרת מזהה איזה מסלול נקנה לפי ה-`ProductID` שמגיע ב-IPN, ולכן **לכל מסלול בדף המכסות צריך שדה "ProductID בקארדקום"** במקום "כתובת התשלום". כתובת התשלום היא שדה אחד משותף בדף המכסות.

**כל הנתונים מדף המכסות, לא מהקוד.** בדף המכסות צריך להוסיף לכל מסלול בתשלום את העמודות:
| עמודה | דוגמה (נורית) | הערה |
|---|---|---|
| שם לתצוגה | נורית | |
| מחיר | 49 | בש"ח |
| מקס' קבלות מסר | 3000 | מספר אמיתי, תמיד |
| מקס' דיאלוגים | 100 | מספר אמיתי, תמיד |
| ProductID בקארדקום | 12345 | חייב להתאים למוצר בעמוד התשלום, כך השרת יודע מה נקנה |

**עיצוב דף המכסות: ההדמיה "ניהול · דף המכסות: מסלולים ומחירים".** בסגנון הרגיל של לוח הבקרה של וורדפרס (לא בעיצוב האפליקציה):
- טבלה אחת למסלולים בתשלום. בכל שורה: פעיל · שם לתצוגה · מחיר · קבלות מסר בחודש · דיאלוגים בחודש · ProductID · **עמודה "כך זה יוצג"** שמתעדכנת בזמן הקלדה (JS), כדי שנורית תראה מיד איך הכרטיס ייראה.
- תיבה נפרדת "עמוד התשלום": שדה אחד לכתובת קארדקום, ומתחתיו תיבת "חלון התשלום פעיל" (עוברת לכאן מהמקום הנוכחי).
- המסלולים החינמיים (אנונימי, רשום) נשארים בטבלה נפרדת כמו היום.
- ההסבר "999999 ומעלה = ללא הגבלה" נמחק.
- ולידציה בשמירה: מחיר ומכסות חייבים להיות מספרים חיוביים; מסלול פעיל בלי ProductID מציג אזהרה; "להציג ללא הגבלה" מסומן עם מספר 0 מציג אזהרה בולטת ("המשתמש לא יוכל להשתמש"); מכסה מעל 1,000 מציגה אזהרה.
- **קארדקום הוא מה שגובה בפועל.** המחיר בדף המכסות הוא לתצוגה בלבד. השם, המחיר וה-ProductID של כל מוצר בקארדקום חייבים להתאים לדף המכסות. בכל IPN נרשמים ביומן ProductID, הסכום והמסלול, ואם הסכום שונה מהמחיר בדף המכסות, נשלחת התראה למייל המנהל.
| פעיל | ☑ | מסלול לא פעיל לא מוצג |
- **"999999 = ללא הגבלה" מבוטל.** תמיד יש מספר אמיתי.

**"ללא הגבלה" בוטל (19.11):** תיבות "להציג ללא הגבלה" יוצאות מדף המכסות, ובכל מקום מוצג המספר האמיתי.
- **כשמשתמש בתשלום מגיע למכסה החודשית:** אם יש מסלול גבוה יותר, מציעים אותו ("החלפת מסלול"); במסלול הגבוה ביותר לא מציעים לשלם שוב. חלון (סעיף 3.4): כותרת "הגעת למכסת השימוש ההוגן" · נוסח: "השימוש שלך החודש הגיע למכסה. היא מתחדשת ב־{תאריך}. אם זה חשוב לך, [כתבו לנו]." · כפתור "הבנתי".

#### 6.10.3 אחרי התשלום
- **אין מסך "ההרשמה הושלמה" באפליקציה.** קארדקום מציגה את אישור התשלום, ומחזירה לאפליקציה.
- כשהמשתמש חוזר, האפליקציה בודקת את `/account/status`. ה-IPN יכול להגיע כמה שניות אחרי. אם המסלול עוד לא התעדכן ומשתמש מנסה להשתמש, **לא פותחים שוב את חלון התשלום**: הכפתור מציג "רגע…", ובודקים שוב כל 2 שניות עד 30 שניות. אם עדיין אין עדכון: שורה "התשלום מתעדכן. זה יכול לקחת עוד דקה. אם משהו לא מסתדר, [כתבו לנו]."

#### 6.10.4 כתבו לנו. הדמיה: "טלפון · כתבו לנו"
- נפתח מהתפריט ☰ ומהקישורים "כתבו לנו" בהודעות השגיאה. מחליף את קישור ה-`mailto`.
- **כותרת:** "כתבו לנו" · **טקסט:** "שאלה, הצעה או משהו שלא עבד כמו שצריך? נשמח לשמוע, ונחזור אלייך/אליך במייל."
- **שדות:** "המייל שלך, לתשובה" (ממולא מראש אם ידוע) · "ההודעה" (5 שורות, עם מיקרופון כמו בתיבת השיחה). **בלי "(לא חובה)"**, שני השדות חובה.
- **כפתורים:** "שליחה" · "ביטול".
- **שרת:** `POST /wp-json/dcard/v1/contact`, שולח עם `wp_mail` אל **doar@nuriteldar.co.il**, בנושא **`** כתבו לנו - הקורא בקלפים **`**, עם `Reply-To` = המייל של המשתמש, כך שלחיצה על "השב" עונה לו ישירות. בגוף ההודעה: ההודעה, השם, לשון הפנייה, המסלול, מזהה המשתמש, הדפדפן ומכשיר. הגבלה: עד 5 הודעות בשעה ממכשיר אחד.
- **משתמש רשום (המייל ידוע):** במקום שדה מייל, שורה: "נחזור אלייך/אליך לכתובת: {מייל}" (לקריאה בלבד). **הסמן נכנס לתיבת ההודעה** כשהחלון נפתח. למשתמש אנונימי: שדה מייל, והסמן בשדה המייל.
- **אחרי שליחה:** וי, "ההודעה נשלחה", "תודה, {שם}. נחזור אלייך/אליך לכתובת {מייל}.", כפתור "סגירה".

**גרסת "תיקון כתובת המייל"** (נפתחת מ"אם הכתובת שגויה, כתבו לנו" בחלון ההצטרפות):
- כותרת: **"תיקון כתובת המייל"**
- שורה לקריאה בלבד: "הכתובת הרשומה: {מייל}".
- **שדה אחד:** "הכתובת הנכונה" (`type=email`). **בלי** שדה מייל לתשובה ובלי תיבת הודעה, כדי שלא יהיו שתי כתובות שונות.
- כפתורים: "עדכון הכתובת" · "ביטול".
- **משתמש שעוד לא שילם אף פעם** (אין לו עסקאות): הכתובת **מתעדכנת מיד** בשרת וב-localStorage (אחרי בדיקה שהיא תקינה ולא שייכת למשתמש אחר). הודעה: "הכתובת עודכנה ל־{מייל חדש}." וחזרה לחלון ההצטרפות עם הכתובת החדשה. בלי עבודה ידנית.
- **משתמש ששילם בעבר:** הבקשה נשלחת למנהל (הכתובת הישנה והחדשה, מזהה המשתמש), כי צריך לעדכן גם בקארדקום. הודעה: "קיבלנו. נעדכן את הכתובת ונחזור אלייך/אליך."
- **כתובת ששייכת למשתמש אחר:** "הכתובת הזו כבר רשומה. אם היא שלך, [כתבו לנו]."

**גרסת "החלפת מסלול"** (נפתחת מ"רוצה להחליף מסלול?" באזור שלי, עד שתיבנה החלפה עצמית):
- כותרת: **"החלפת מסלול"**
- טקסט: "{שם}, כרגע את/ה במסלול **{מסלול}**. לאיזה מסלול תרצה/י לעבור?"
- **בחירה:** כפתורי רדיו רגילים, אחד לכל מסלול פעיל **חוץ מהנוכחי**, בפורמט "{שם} · {מחיר} ₪ לחודש".
- תיבת הערה (לא חובה), עם מיקרופון.
- כפתורים: "שליחת הבקשה" · "ביטול".
- **אחרי שליחה:** וי, "קיבלנו את הבקשה", "{שם}, ניצור איתך קשר בהקדם לשינוי המסלול."
- **המייל למנהל:** נושא `** כתבו לנו - הקורא בקלפים ** – החלפת מסלול`, ובגוף: המסלול הנוכחי, המסלול המבוקש, ה-RecurringId, המייל ומזהה המשתמש.
- **אם השליחה נכשלה:** שורת שגיאה עם [ניסיון חוזר], ו**הטקסט שנכתב לא נמחק**.

### 6.11 האזור שלי. הדמיה: "טלפון · האזור שלי"
מסך מלא (לא חלון). **כפתור חזרה בולט:** בראש המסך, חץ → ולידו המילה "חזרה", גובה 44px, טקסט 16px. (לא עיגול קטן עם חץ בלבד.) במחשב: עמודה אחת ממורכזת ברוחב 560px. ארבעה חלקים, בסדר הזה:

**1. המסלול שלי**
- כרטיס: שם המסלול, מחיר "לחודש", ו"החיוב הבא: {תאריך}". (מועד החידוש של השימושים זהה למועד החיוב, ולכן לא כותבים אותו שוב.)
- **השימוש החודש:** שני פסים, "קבלות מסר: 12 מתוך 80" ו"דיאלוגים מכוונים: 4 מתוך 30". בלי שורת "מתחדש ב־". **חישוב:** `used = max(0, quota - remaining)`, ואם `remaining > quota` (למשל המכסה שונתה אחרי הרכישה) מציגים `quota = remaining`. אף פעם לא מספר שלילי, ואין כוכבית ליד מספר. פס: גובה 8px, רקע `--blush`, מילוי `--bordeaux`, `role="progressbar"`. 
- מתחת: "רוצה להחליף מסלול? [כתבו לנו]". החלפה עצמית תיבנה בהמשך.
- **משתמש במסלול חינמי:** שם המסלול מוצג כ**"אורח"** (לא "חינמי"), כמה שימושים נותרו, וכפתור ראשי "הצטרפות למסלול" שפותח את חלון ההצטרפות (6.10.2).
- **ביטול המנוי:** קישור שקט "ביטול המנוי" מתחת לכרטיס. פותח חלון (3.4):
  - כותרת: "לבטל את המנוי?"
  - טקסט: "המנוי יישאר פעיל עד **{תאריך}**, ולא תחויב/י שוב."
  - "נשמח לדעת למה (לא חובה)": תגיות לבחירה אחת: "יקר לי" · "לא משתמש/ת מספיק" · "קיבלתי מה שחיפשתי" · "אחר".
  - כפתורים: **"להישאר במנוי"** (ראשי, מלא) · "כן, לבטל את המנוי" (משני, מסגרת). ההשארה היא הכפתור הבולט. **ריחוף על הכפתור המשני לא ממלא אותו:** רק רקע `--blush`, הטקסט והמסגרת נשארים בורדו (לנטרל את עיצוב הכפתורים של התבנית, סעיף 3.1).
  - **אחרי ביטול:** תגית בכרטיס "בוטל · פעיל עד {תאריך}", שורה "המנוי בוטל. אפשר להמשיך להשתמש עד {תאריך}, ולא יהיו חיובים נוספים. אישור נשלח אלייך/אליך במייל.", והקישור "ביטול המנוי" נעלם.
- **הביטול בשרת:** `POST /account/cancel`:
  1. קריאה ל-API של הוראות הקבע בקארדקום (`docs/cardcom-api/`): `Operation=Update`, `RecurringPayments.RecurringId`, `RecurringPayments.IsActive=false`. **לשם כך צריך לשמור את `RecurringId` של כל משתמש מה-IPN** (שדה חדש בטבלה, ולהעלות `DCARD_DB_VERSION`).
  2. רק אם קארדקום אישרה: שומרים `cancelled_at` ו**`cancel_reason`** (עמודות חדשות, והסיבה מוצגת גם בטבלת הלקוחות באדמין). **לא משנים את המסלול ולא את `plan_expires_at`** עד התאריך.
  - **עד שיהיו פרטי ה-API של קארדקום (מצב ביניים):** הבקשה נשמרת (`cancel_requested_at` + הסיבה), המשתמש רואה את אותו אישור, ולמנהל נשלח מייל "לבטל ידנית בקארדקום את הוראת הקבע של {מייל}". ברגע שה-API מחובר, אותו כפתור עובד אוטומטית.
  3. מייל אישור למשתמש, ומייל למנהל עם הסיבה.
- **אחרי התאריך: מצב "מבוטל", לא חינמי.** משתמש שמנוי שלו בוטל (או לא חודש) עובר למצב `cancelled` עם 0 שימושים, **לא** למסלול החינמי. בכניסה הבאה, ברגע שהוא מזוהה, נפתח מיד חלון ההצטרפות (6.10.2) עם הכותרת "{שם}, טוב לראות אותך שוב" במקום "נמשיך יחד?". הבדיקה היומית מעבירה ל-`cancelled`, לא ל-`free`.
  4. **אם קארדקום נכשלה:** הודעה "לא הצלחנו לבטל כרגע. אפשר לנסות שוב, או [כתבו לנו]." ומייל דחוף למנהל. **אסור להציג "בוטל" אם החיוב לא באמת הופסק.**

**2. הפרטים שלי**
- **הסדר:** שם (אותה ולידציה כמו בכל מקום, כולל גרש) · **מייל, בשורה אחת: "מייל: {כתובת}"** (לקריאה בלבד, מיד מתחת לשם) · איך לפנות אליך (רדיו רגיל) · טלפון (**בלי** "(לא חובה)", השדה פשוט לא חובה) · כפתור "שמירת השינויים". שינוי שם או לשון פנייה מתעדכן גם ב-localStorage.
- **מייל: לקריאה בלבד, בלי קישור.** המייל הוא גם הזיהוי בקארדקום: אם ישתנה אצלנו ולא אצלם, החידושים החודשיים לא יתחברו למשתמש. שינוי מייל ייבנה יחד עם הכניסה בקוד, ויעדכן גם את קארדקום.

**3. היסטוריית תשלומים**
- שורה לכל חיוב: **"{תאריך} · {שם המסלול}" בשורה אחת**, סכום, וקישור "חשבונית" אם קארדקום מחזירה קישור. מתוך `wp_dcard_transactions`.
- אין תשלומים: "עוד לא היו תשלומים."

**4. החשבון**
- **"התנתקות מהמכשיר הזה": מוסתר בשלב הזה.** בלי כניסה בקוד, מי שמתנתק לא יכול לחזור לבד, וכל התנתקות הופכת לפנייה ידנית. יחזור יחד עם הכניסה בקוד.
- **"מחיקת החשבון מהאפליקציה"** (בצבע `--error`): חלון אישור עם הקלדת המילה "מחיקה". מוחק את פרטי המשתמש מהשרת. **אם יש מנוי פעיל, קודם מבטלים אותו בקארדקום** (כמו בביטול), ורק אז מוחקים. רשומות התשלום נשמרות בלי פרטים מזהים (לצורכי הנהלת חשבונות).

**נדחה לשלב האריזה (רשום ב-todo.md):** כניסה עם קוד למייל ממכשיר אחר (ואיתה: התנתקות ושינוי מייל), החלפת מסלול עצמית.

**החלפת מסלול עצמית (לשלב האריזה):** "החלפת מסלול" פותח את חלון ההצטרפות. כשמגיע IPN של מסלול חדש למשתמש שיש לו הוראת קבע פעילה אחרת, השרת **מבטל אוטומטית** את הוראת הקבע הקודמת דרך ה-API (לפי `RecurringId` השמור). בלי עבודה ידנית.

## 7. ערבוב ושליפה: מפרט מלא

> **עדכון 19.11 (גובר על מה שכתוב בהמשך הסעיף אם יש סתירה):**
> - **הקלפים כבר בתנועה כשהמסך מופיע.** אין שלב המתנה, ואין כפתור מושבת. בדיקת הקרדיטים נעשית **לפני** המעבר למסך (על כפתור המסלול, שמציג "רגע…"), כך שכשמסך הערבוב נפתח, אפשר לבחור מיד.
> - **תנועה רציפה בלולאה:** שתי חבילות, ריפל ביניהן, ואז זרימה מצד לצד (קלף אחר קלף, הלוך וחזור), וחוזר חלילה, עד שהמשתמש בוחר. בלי עצירות.
> - **בחירה בכל רגע, גם בשנייה הראשונה וגם באמצע ריפל:** נגיעה בכל מקום על אזור הקלפים (לא רק על קלף מסוים), או לחיצה על "שליפת קלף". הקלף שנבחר: הקלף שבתנועה, או אם אין כזה, הקלף העליון בערימה הקרובה לנגיעה. **מיד בבחירה התנועה נעצרת**, שאר הקלפים מתאספים לערימה אחת, והקלף הנבחר עולה, מתהפך ומסתובב (כמו היום).
> - **כל אזור הקלפים הוא כפתור אחד** (`role="button"`, `aria-label="שליפת קלף"`, `tabindex="0"`, Enter/רווח בוחרים), ולא כל קלף בנפרד.
> - **שגיאה בשליפה** (השרת לא ענה תוך 8 שניות או החזיר שגיאה): הקלף חוזר לערימה, **התנועה ממשיכה**, הכפתור "שליפת קלף" **נשאר גלוי ופעיל**, ומתחת שורת שגיאה עם [ניסיון חוזר]. אסור שהמסך ייתקע.

### 7.1 העיקרון
המשתמש צריך **להרגיש שהוא בוחר**. לכן הקלפים לא נחים על השולחן. הם זורמים מערימה לערימה, והמשתמש **עוצר** את הזרימה. הקלף שבתנועה באותו רגע הוא שלו.

### 7.2 האקראיות בצד השרת (חובה)
- **האנימציה רק מציגה.** איזה קלף מבין ה־72 ייצא נקבע **בשרת**, ברגע הלחיצה, למשל בבקשת AJAX קיימת או חדשה, עם `random_int()` של PHP.
- הלקוח שולח בקשה, מקבל בחזרה `{ id, image_url, alt }`, וטוען את התמונה **מראש** (`new Image()`). ההיפוך מתחיל רק כשהתמונה נטענה **וגם** עבר זמן ההרמה המינימלי.
- **אם השרת לא עונה תוך 8 שניות, או מחזיר שגיאה:** הקלף חוזר לערימה, הזרימה ממשיכה, **וכפתור "שליפת קלף" חוזר להופיע**. במקום שורת ההנחיה מופיעה שורת השגיאה (סעיף 3.5): "הקלף לא נשלף בגלל תקלה בחיבור." עם כפתור **"ניסיון חוזר"**, שעושה בדיוק את מה שעושה "שליפת קלף". המשתמש אף פעם לא נשאר בלי דרך להמשיך.
- הקלפים בחפיסה המונפשת הם **גבי קלפים בלבד**, בלי קשר לתמונות האמיתיות.

### 7.2ב חיוב קרדיט רק על שירות שניתן
**כלל: אסור לחייב קרדיט על קריאה שלא הגיעה למשתמש.**
- **מתי מורידים קרדיט:** רק אחרי ש**התשובה הראשונה של הקורא נוצרה בהצלחה ונשלחה** (השרת קיבל תשובה מלאה מה-AI והחזיר 200). לא בשליפת הקלף, ולא בתחילת הסשן.
  - קבלת מסר: קרדיט אחד, כשהמסר נמסר.
  - דיאלוג מכוון: קרדיט אחד לכל השיחה, כשההודעה הראשונה של הקורא נמסרה.
- **אם ה-AI נכשל, חרג מזמן או החזיר תשובה ריקה:** לא מורידים. אם כבר ירד, מחזירים אוטומטית, ורושמים ביומן.
- **ניסיון חוזר לא מחייב שוב:** לכל בקשה יש מזהה (`request_id`). אם החיבור נקטע אחרי שהשרת כבר יצר תשובה, "ניסיון חוזר" מקבל **את אותה תשובה** מהשרת, בלי קריאה חדשה ל-AI ובלי חיוב נוסף.
- **אדמין:** בטבלת הלקוחות, פעולה "החזרת קרדיט" (מסר או דיאלוג), עם רישום ביומן מי ומתי.

### 7.2 עיקרון על: לא עוצרים שיחה באמצע
- **בדיקת קרדיטים, חלון הרשמה וחלון תשלום מופיעים רק בתחילת שיחה חדשה:** בלחיצה על "דיאלוג מכוון" או "קבלת מסר אישי" במסך הבית. **אף פעם** לא באמצע שיחה.
- **בתוך שיחה שהתחילה, הכול כלול:** קלף נוסף (עד 3), כל התורות, והמעבר ממסר לדיאלוג מכוון. אין בדיקת קרדיטים על "צריך עוד קלף?" ועל תורות בשיחה. (בכך מבוטלת הבדיקה שהוספנו ב-6.10.1 על "צריך עוד קלף?".)
- **המעבר ממסר לדיאלוג** הוא המקרה היחיד שבו מורידים קרדיט דיאלוג באמצע. אם אין קרדיט דיאלוג, **ממשיכים בכל זאת** את השיחה הזו, ורושמים ביומן. לא עוצרים את המשתמש.
- **שמירת השאלה:** כשחלון הרשמה או תשלום נפתח בתחילת שיחה, השאלה שהמשתמש כתב והמסלול שבחר נשמרים (localStorage, עם תוקף של שעה). אחרי הרשמה, או אחרי חזרה מקארדקום ועדכון המסלול, השאלה חוזרת לתיבה **והפעולה ממשיכה לבד** לערבוב. המשתמש לא כותב שוב.

### 7.2ג חזרה מתשלום
- בזמן ההמתנה לעדכון המסלול: **חלון עם הודעה גלויה** "בודקים את התשלום שלך…" (עם סימן טעינה), לא כפתור תקוע על "רגע…". בדיקה ראשונה מיד, ואחר כך כל 2 שניות, עד 30 שניות.
- **הצלחה:** החלון נסגר, והשאלה השמורה ממשיכה לבד לערבוב (7.2).
- **לא התעדכן אחרי 30 שניות:** "התשלום התקבל ואנחנו משלימים את העדכון. זה יכול לקחת כמה דקות. אפשר לנסות שוב בעוד רגע." עם [בדיקה חוזרת] ו[כתבו לנו], **ומייל מיידי למנהל.** **אסור לפתוח שוב את חלון התשלום** למשתמש שחזר מקארדקום ב־30 הדקות האחרונות, ואסור להריץ אוטומטית את הפעולה השמורה.

### 7.2א קרדיטים: בודקים לפני שמערבבים
- **לפני שמסך הערבוב נפתח** (בלחיצה על "קבלת מסר אישי", "דיאלוג מכוון" או "צריך עוד קלף?"), שואלים את השרת אם נשאר למשתמש קרדיט **לסוג השימוש הזה**. אם לא, **לא מתחילים לערבב**, ופותחים את החלון המתאים לפי הטבלה:

| מצב המשתמש | איזה חלון נפתח |
|---|---|
| **אנונימי** (לא השאיר מייל) | **חלון רישום המייל** הקיים, בעיצוב של סעיף 3.4. אחרי רישום מוצלח מתווספים קרדיטים, ו**הפעולה ממשיכה אוטומטית** (מסך הערבוב נפתח) בלי שהמשתמש צריך ללחוץ שוב |
| **רשום, וחלון התשלום פעיל** (`KB_PAYWALL_ENABLED = true`) | **חלון התשלום** (`triggerPaymentWall`) |
| **רשום, וחלון התשלום כבוי** (תקופת הבדיקות) | חלון **"נגמרו השימושים לתקופת הניסיון"** (סעיף 3.5א) |

- **השרת מבדיל בין "נגמרו הקרדיטים" לבין תקלה:** בתשובה ברורה, למשל HTTP 402 או `{ "error": "credits_exhausted", "mode": "message" }`, ולא בשגיאה כללית.
- **לחיצה על כפתור מסלול תמיד נותנת תגובה גלויה תוך שנייה:** או שמסך הערבוב נפתח, או שנפתח החלון המתאים, או שמופיעה שורת שגיאה. **אסור שלחיצה "לא תעשה כלום".** בזמן הבדיקה מול השרת, הכפתור מציג "רגע…" ומושבת.
- **אם בכל זאת מגיעה תשובת "נגמרו הקרדיטים" ברגע השליפה:** עוצרים את הזרימה ומחזירים את הקלף לערימה (בלי "ניסיון חוזר", כי ניסיון חוזר לא יעזור), ופותחים את אותו חלון.
- **"ניסיון חוזר" מוצג רק לתקלות שניסיון חוזר יכול לפתור:** רשת, timeout או שגיאת שרת זמנית (5xx).

### 7.4 רצף השלבים

| # | שלב | מה רואים | זמן |
|---|---|---|---|
| 0 | `stack` | ערימה אחת במרכז. כל קלף מוזז 1.2px כלפי מעלה ביחס לקודם (עובי של חפיסה), עם סיבוב קטן ואקראי של ±1.5° | 500ms |
| 1 | `split` | החפיסה נחתכת לשתיים. החצי התחתון זז ל־‎-PX והעליון ל־+PX, בזווית של ‎∓6°. כל קלף מתעכב `(p % 4) × 30ms` | 650ms |
| 2 | `riffle` | **ריפל:** הסדר החדש נקבע בשזירה אקראית של שתי החפיסות (ראו `riffle()`). כל קלף חוזר למרכז, והעיכוב שלו לפי מקומו החדש, `p × 60ms`, כך שהם נוחתים אחד אחד מלמטה למעלה, לסירוגין משני הצדדים | 1000ms |
| 3 | `stack` | יישור קצר של הערימה | 300ms |
| — | | **שלבים 1–3 חוזרים פעמיים** | |
| 4 | `flow` | כל הקלפים נערמים **בצד ימין** (+PX). מכאן קלף אחרי קלף עובר לערימה בצד **שמאל** (‎-PX), כל `FLOW_MS`, עם מעבר של 300ms. הקלף שבתנועה מקבל הטיה נוספת של ±4° בכיוון התנועה. כשהערימה המקורית מתרוקנת, **הכיוון מתהפך**, וכך הלאה בלי הפסקה, עד שהמשתמש שולף. **הכפתור מופעל רק מתחילת השלב הזה** | ∞ |
| 5 | `drawn: lift` | **ברגע הלחיצה, בלי שום השהייה: כפתור "שליפת קלף" וגם שורת ההנחיה שמעליו נעלמים**, עוד לפני שהקלף עולה, וההקשה על קלפים מבוטלת. הזרימה נעצרת. הקלף הנבחר עולה למרכז (`x=0, y=PY`) ומוגדל פי `S`. שתי הערימות זזות `PUSH` הצידה ו־`PUSHY` למטה, ב־600ms. במקביל נשלחת הבקשה לשרת | 700ms לפחות |
| 6 | `flipped` | **ההיפוך נעשה כשהקלף עדיין עומד:** `rotateY(180deg)` ב־750ms. הצד הקדמי מופיע | 750ms |
| 7 | `land` | **הסיבוב לרוחב:** `rotate(90deg)`, וההגדלה משתנה מ־`S` ל־`SL`. **התמונה ממלאת את כל הקלף**, עם מסגרת לבנה דקה בלבד | 750ms |
| 8 | סיום | מופיע הטקסט "זה הקלף הנבחר…" (באזור `aria-live`), ומתחתיו הכפתור "להמשך הקריאה" | — |

**איזה קלף נבחר:**
- **לחיצה על "שליפת קלף":** הקלף **האחרון שזז**, כלומר זה שבתנועה או שזה עתה נחת.
- **הקשה ישירה על קלף בכל אחת מהערימות:** הקלף שהוקש. הקשה עובדת רק בשלב `flow`.
- בשני המקרים, התמונה שמתגלה היא זו **שהשרת החזיר**.

### 7.6 קוד ייחוס (JavaScript רגיל)

> זה קוד **לייחוס**. אפשר להתאים אותו למבנה הקיים, אבל לשמור על הלוגיקה והתזמונים.

```js
// kb-shuffle.js
function kbShuffle(stage, opts) {
  // opts: { mobile, fetchCard: () => Promise<{id,image_url,alt}>, onReveal(card), onBusyChange(busy), onHint(key) }
  const P = opts.mobile
    ? { N:12, CW:86,  CH:129, PX:112, BT:150, PY:-80,  S:1.55, SL:1.5, PUSH:30, PUSHY:30, FLOW:170 }
    : { N:12, CW:130, CH:195, PX:190, BT:200, PY:-110, S:1.7,  SL:1.5, PUSH:40, PUSHY:60, FLOW:170 };
  const reduce = matchMedia('(prefers-reduced-motion: reduce)').matches;
  const cards = [], timers = [];
  let order = [...Array(P.N).keys()], A = [], B = [], dir = 'AB', phase = 'stack';
  let z = {}, zc = P.N, last = null, chosen = null, flowTimer = null;
  const jit = (id, k) => (((id * 73 + k * 31) % 11) - 5) / 5;           // ‎-1..1, קבוע לכל קלף
  const later = (ms, fn) => timers.push(setTimeout(fn, ms));

  stage.style.setProperty('--cw', P.CW + 'px'); stage.style.setProperty('--ch', P.CH + 'px');
  stage.style.setProperty('--bt', P.BT + 'px');
  for (let id = 0; id < P.N; id++) {
    const el = stage.querySelector(`[data-card="${id}"]`);              // נבנו מראש ב-HTML
    el.addEventListener('click', () => pick(id));
    cards.push(el);
  }

  function setT(id, { x=0, y=0, r=0, ry=0, s=1, dur=420, delay=0, zi }) {
    const el = cards[id];
    el.style.transition = reduce ? 'none' : `transform ${dur}ms cubic-bezier(.2,.7,.2,1) ${delay}ms`;
    el.style.transform = `translate(${x}px,${y}px) rotate(${r}deg) rotateY(${ry}deg) scale(${s})`;
    if (zi !== undefined) el.style.zIndex = zi;
  }
  function render() {
    for (let id = 0; id < P.N; id++) {
      if (id === chosen) continue;
      const p = order.indexOf(id);
      if (phase === 'stack')  setT(id, { y: -p*1.2, r: jit(id,4)*1.5, delay: p*25, zi: p });
      if (phase === 'split') { const L = p < P.N/2;
        setT(id, { x: L ? -P.PX : P.PX, y: -(L ? p : p - P.N/2)*1.5, r: L ? -6 : 6, delay: (p%4)*30, zi: p }); }
      if (phase === 'riffle') setT(id, { y: -p*1.2, r: jit(id,4)*1.5, dur: 340, delay: p*60, zi: p });
      if (phase === 'flow' || phase === 'drawn') {
        const ia = A.indexOf(id), ib = B.indexOf(id);
        const push = phase === 'drawn' ? P.PUSH : 0, dy = phase === 'drawn' ? P.PUSHY : 0;
        let x = ia >= 0 ? P.PX + push : -P.PX - push, y = -(ia >= 0 ? ia : ib) * 1.2 + dy;
        let r = jit(id,5) * 3; if (id === last && phase === 'flow') r += dir === 'AB' ? -4 : 4;
        setT(id, { x, y, r, dur: phase === 'drawn' ? 600 : 300, zi: z[id] ?? p });
      }
    }
  }
  function riffle(o) {                                                    // שזירה אקראית
    const cut = Math.floor(o.length/2) + (Math.random() < .5 ? -1 : 1);
    const a = o.slice(0, cut), b = o.slice(cut), out = [];
    while (a.length || b.length) out.push((a.length && (!b.length || Math.random() < .5)) ? a.shift() : b.shift());
    return out;
  }
  function step() {                                                       // מעבר קלף אחד
    const src = dir === 'AB' ? A : B, dst = dir === 'AB' ? B : A;
    const id = src.pop(); dst.push(id); z[id] = ++zc; last = id;
    if (!src.length) dir = dir === 'AB' ? 'BA' : 'AB';
    render();
  }
  async function pick(id) {
    if (phase !== 'flow' || chosen !== null) return;
    clearInterval(flowTimer); phase = 'drawn'; chosen = id;
    A = A.filter(x => x !== id); B = B.filter(x => x !== id);
    opts.onBusyChange(true); render();
    setT(id, { x: 0, y: P.PY, r: -1, s: P.S, dur: 750, zi: 9999 });       // lift
    const minLift = new Promise(r => setTimeout(r, 700));
    try {
      const card = await Promise.race([opts.fetchCard(), new Promise((_, rej) => setTimeout(() => rej('timeout'), 8000))]);
      const img = cards[id].querySelector('.kb-front-inner img');
      await new Promise((res, rej) => { img.onload = res; img.onerror = rej; img.src = card.image_url; img.alt = card.alt; });
      await minLift;
      setT(id, { x: 0, y: P.PY, r: -1, ry: 180, s: P.S, dur: 750, zi: 9999 });   // flip (עומד)
      later(800, () => {
        setT(id, { x: 0, y: P.PY, r: 90, ry: 180, s: P.SL, dur: 750, zi: 9999 }); // land (לרוחב)
        later(800, () => { opts.onHint('revealed'); opts.onReveal(card); });
      });
    } catch (e) {                                                          // החזרה לזרימה ושגיאה
      chosen = null; phase = 'flow'; A.push(id); render(); opts.onHint('error'); opts.onBusyChange(false);
      flowTimer = setInterval(step, P.FLOW);
    }
  }
  function start({ skipRiffle = false } = {}) {                          // skipRiffle: ל"קלף נוסף"
    opts.onBusyChange(true); opts.onHint('shuffling'); render();
    let t = 400;
    if (!skipRiffle && !reduce) for (let k = 0; k < 2; k++) {
      later(t, () => { phase = 'split'; render(); }); t += 650;
      later(t, () => { phase = 'riffle'; order = riffle(order); render(); }); t += 1000;
      later(t, () => { phase = 'stack'; render(); }); t += 300;
    }
    later(t, () => { phase = 'flow'; A = reduce ? order.slice(0, P.N/2) : order.slice(); B = reduce ? order.slice(P.N/2) : [];
      render(); opts.onHint('flowing'); opts.onBusyChange(false); });
    if (!reduce) later(t + 650, () => { flowTimer = setInterval(step, P.FLOW); });
  }
  return {
    start,
    drawNow: () => pick(last ?? A[A.length - 1]),                          // כפתור "שליפת קלף"
    destroy: () => { timers.forEach(clearTimeout); clearInterval(flowTimer); }
  };
}
```

### 7.7 נגישות ומקלדת
- כפתור "שליפת קלף" הוא הדרך העיקרית לשלוף. ההקשה על קלף היא תוספת.
- שורת הסטטוס נמצאת ב־`aria-live="polite"`, וכל הטקסטים שלה מגיעים מסעיף 6.4.
- כל הקלפים המונפשים הם `<button>` עם `aria-label="קלף"`. Tab עובר ביניהם רק בשלב `flow`. בשאר הזמן יש להם `tabindex="-1"`.
- אחרי החשיפה הפוקוס עובר לכפתור "להמשך הקריאה".

### 7.8 תנועה מופחתת (`prefers-reduced-motion: reduce`)
- **בלי ריפל ובלי זרימה.** מוצגות שתי ערימות סטטיות, והכפתור מופעל מיד.
- **אחרי השליפה:** הקלף מופיע ישר במצב הסופי (לרוחב, התמונה מלאה), עם `opacity` של 0→1 ב־200ms.

### 7.9 בדיקות לשלב הזה
- [ ] הכפתור מושבת בזמן הריפל ומופעל כשמתחילה הזרימה.

- [ ] הזרימה מחליפה כיוון כשהערימה מתרוקנת, ולא נתקעת.
- [ ] לחיצה בכל רגע בזמן הזרימה שולפת את הקלף שבתנועה.
- [ ] הקשה על קלף באמצע הערימה שולפת אותו.
- [ ] התמונה **מגיעה מהשרת**. ב-Network רואים בקשה אחת ברגע השליפה, ובקוד ה-JS אין רשימת תמונות.
- [ ] הקלף מתהפך כשהוא עומד, ורק אחר כך מסתובב לרוחב. התמונה ישרה וממלאת את כל הקלף.
- [ ] **בטלפון אמיתי:** אין שום צבע (אדום, ורוד או אחר) בפינות הקלף בזמן ההיפוך ואחריו.
- [ ] הקלף הנבחר לא מכסה את הערימות. הן זזות הצידה ולמטה.
- [ ] כשהשרת מחזיר שגיאה, מופיעה שורת "ניסיון חוזר", הזרימה ממשיכה **וכפתור "שליפת קלף" חוזר**. (לבדוק עם הדמיית שגיאה, למשל בכיבוי הרשת ב-DevTools.)
- [ ] ברגע השליפה נעלמים גם הכפתור וגם שורת ההנחיה, בלי השהייה.
- [ ] הטקסטים הם בדיוק אלה שבסעיף 6.4: הכפתור "שליפת קלף" (לא "בחר קלף"), וההנחיה בלשון הפנייה.
- [ ] בטלפון (רוחב 360–430px) הכול נכנס בלי גלילה אופקית.
- [ ] עם תנועה מופחתת אין אנימציות.
- [ ] בעזיבת המסך כל ה־timers מתנקים (`destroy`).

## 8. מה **לא** עושים בשלב הזה
- לא בונים את "האזור שלי", לא את מסך המסלולים ולא חיבור סליקה.
- **חלון ההרשמה בתשלום מבוטל זמנית לנסיינים.** זו **הגדרה בדף המכסות בניהול וורדפרס**, לא קבוע בקוד:
  - תיבת סימון: **"חלון התשלום פעיל"** (ברירת מחדל: כבוי בתקופת הבדיקות). בקוד היא נקראת `KB_PAYWALL_ENABLED`.
  - ליד התיבה, הסבר קצר: "כשכבוי: משתמש רשום שנגמרו לו הקרדיטים יראה 'נגמרו השימושים לתקופת הניסיון' במקום חלון התשלום."
  - **מחוון למנהל בלבד:** כשהתשלום כבוי, מנהל מחובר רואה באפליקציה תווית קטנה בפינה, "מצב בדיקות: תשלום כבוי". משתמשים רגילים לא רואים אותה.
- לא משנים את ה-prompts של ה-AI, חוץ מהסרת ההזמנה ללחוץ על "להמשיך ולהעמיק בשיחה" (סעיף 6.6).

## 9. סדר העבודה ובקשות מוכנות להדבקה

> מומלץ להתחיל כל שלב ב־**Plan mode** (Shift+Tab) ולצרף צילומי מסך מההדמיה.

**שלב 1: בסיס**
> קרא את `docs/design-spec.md`, סעיפים 0–4. צור קובץ CSS חדש עם המשתנים מסעיף 1, טען את Rubik, והגדר את ארבעת סוגי הכפתורים, שדות הקלט, הכותרת העליונה והלוגו החדש. החל אותם על כל המסכים הקיימים בלי לשנות את המבנה שלהם. קודם הצג תוכנית ופרט אילו קבצים ישתנו.

**שלב 2: כניסה ומסך הבית**
> יישם את סעיפים 6.1–6.3 לפי `docs/design-spec.md` וצילומי המסך המצורפים: דף הכניסה לביקור ראשון בלבד, חלון "נעים להכיר" ומסך הבית. הקפד על הטקסטים המדויקים ועל לשון הפנייה. הוסף את תפריט ☰ (סעיף 5) והעבר אליו את "הנחיות" ו"כתבו לנו". "האזור שלי" לא מוצג.

**שלב 3: ערבוב ושליפה**
> יישם את סעיף 7 במלואו לפי `docs/design-spec.md`. הקלף נבחר בשרת (7.2). השתמש בקוד הייחוס מ־7.6 והתאם אותו למבנה הקיים. בסוף עבור על רשימת הבדיקות ב־7.9 ודווח על כל סעיף.

**שלב 4: הקריאה**
> יישם את סעיפים 3.5 ו־6.5–6.8: מבנה הצ'אט עם שאלה וקלפים קבועים, שיחה שנגללת ותיבה קבועה בתחתית, הודעות ה-AI בלי בועה, כפתורי הפעולות, אזור "רוצה להעמיק?", חלון המייל במקום `window.prompt`, חלון המשוב מהקישור "לתת משוב" והודעת השגיאה החדשה. מחק את התיבה "שתף אותנו בתחושות שלך". "קלף נוסף" משתמש בערבוב מסעיף 7 עם `skipRiffle: true`.

**שלב 5: טלפון ובדיקה כללית**
> עבור על כל המסכים ברוחב 375px וב־1280px. ודא שאין גלילה אופקית, שאין אף `alert`/`confirm`/`prompt` בקוד (סעיף 3.5א), שיעדי הלחיצה הם 44px לפחות, שהפוקוס גלוי, ושלשון הפנייה מתחלפת בכל הטקסטים מסעיף 6. בטל זמנית את חלון התשלום (סעיף 8). דווח מה תיקנת.
